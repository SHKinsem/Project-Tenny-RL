# 腿力矩上限的来源与回放占用

2026-11-16只读核对。**±1N·m是早期流程实验的暂定尺度，未找到硬件规格或动态能力计算支持它；本轮35条确定性回放没有发生硬限幅裁剪，但存在腿力动作接近满幅。** 这两项事实不能合并成“1N·m已证明足够”。

## 参数来源

- [实验说明](../experiments/torque200/README.md)明确写腿部1N·m是流水线实验的初始动作尺度，并非已优化或验证足以平衡的值；[默认配置](../experiments/torque200/legwheel/config.py)有`provisional thigh scale for smoke validation`注释。
- [环境初始化](../experiments/torque200/legwheel/env.py)把配置尺度写入MuJoCo `actuator_ctrlrange`与`actuator_forcerange`，实验XML也将腿motor范围设为±1。它确实是运行限幅，不只是页面单位。
- 当前Git最早可见的`17a79a5`（2026-11-14）初始提交已包含上述配置和“暂定尺度”说明。随后`663824e`的虚拟腿力实现继承它。最早入库不等于最早产生时间，不能据此补造更早的决策过程。
- ±24N·m继承[原参考XML](../reference/mujoco_legwheel_rl_public/assets/legwheel_robot2_stl_nolinkage6_terrain.xml)的位置伺服：`kp=120, kv=80, gear=1`、目标角区间[-.5,0]、输出force范围±24。未找到24对应哪款硬件或如何推导的说明；它也不是本轮确认的实机额定能力。

## 动作范围与硬限幅分开

[hybrid/core.py](../experiments/torque200/hybrid/core.py)使用`F_scale = 0.9 * torque_limit / Jmax`反推虚拟腿力范围。`Jmax`又是扫描最大值上浮1%的数值界限。当前每腿约±8.8715N，策略动作先限制为[-1,1]，再按`tau = J(q) * F_scale * action`映射，最后裁剪到±1N·m。

因此在标定几何区域，动作满幅通常只产生约0.89N·m。没碰到1N·m并不代表没有用尽当前动作包络；仅提高XML硬上限，也不会自动改变冻结的力尺度或现有策略输出。改变能力范围需要显式重新标定和匹配对照，不能直接把24当作新推荐值。

## 本轮回放结果

BC初始化、原奖励6秒训练三个seed、30秒训练三个seed，各使用相同五个固定初态，共35条首回合。原生评估器重放的动作/qpos/qvel/ctrl与原保存数组逐点一致；只统计首次环境终止前。

- 首回合总22,766个控制步、91,064个物理子步，原生`hybrid/saturation_fraction`的首回合累加值全部为0。该指标每控制周期对所有物理子步的非负裁剪值取max；**零可以推出每个子步均无安全保护之后的raw扭矩请求超限**，非零则不能直接解释为裁剪时间占比。
- 力矩幅值仍来自100Hz末物理子步ctrl样本。已审计单位增益、单位gear、无动态motor，故由其力律推得理想实际力矩；不是实机力矩测量，也未逐子步采集qfrc峰值。这些样本两腿全局最大值约0.8904/0.8867N·m。
- 腿动作≥95%范围是虚拟腿力包络占用，不是±1N·m硬裁剪。按35条轨迹实际控制区间时间加权：

| 阶段 | 左腿动作≥95% | 右腿动作≥95% |
| --- | --- | --- |
| 起始1秒 | 0.0% | 23.0% |
| 首秒结束至首次持续离带起点 | 0.0% | 0.77% |
| 该起点之后 | 22.62% | 35.74% |

“持续离带”指首秒后，俯仰误差>10°、真实XY位移>5cm、平面速度>0.1m/s任一条件连续超出0.2秒，边界取该段起点。此前可有短暂越界，此后也可能短暂回带；阶段名称不是稳定性或因果判定。右腿启动时也有明显近满幅，不能说所有满幅都发生在失稳后。

这些数据不支持“平衡阶段一直在被±1硬裁剪”的解释；也不排除动作范围对启动或恢复能力的影响。未比较其他上限，未测原位置模式实际用了多少24N·m余量，不能由此判定增大上限会改善平衡。固定确定性回放占用不等于PPO训练时随机动作的历史占用。
