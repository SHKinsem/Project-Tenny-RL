# 工作台控制、保存与加载

2026-11-15 更新。当前正式工作台与训练器通过版本化文件协议连接，旧运行不热更新；能力由真实运行状态决定。接口总览见[后端能力](workbench-backend.md)，发布与验收见[生产整合](workbench-production.md)，累计格式见[checkpoint 合同](checkpoint-progress.md)。

## 训练控制

`POST /training` 接受 `start`、`stop`、`pause`、`resume`、`save`。

| 操作 | 生效边界 | 成功判据 |
| --- | --- | --- |
| 暂停 / 原位继续 | 已完成参数计算的 Python 回调 | 对应 `workbench_control_result.status=applied` |
| 手动保存 | 同一安全边界，暂停中也可执行 | 对应 `workbench_save_results.status=completed`，有真实路径和 ID |
| 停止并保存 | 原有协作停止边界 | 进程结束且最终产物验证通过 |

暂停保留同一个进程、网络与优化器，不重新调用 PPO。暂停时间从本轮预算和累计训练时间中扣除。准备阶段的暂停意图需要等待安全边界；界面显示等待，而不是提前声称暂停完成。暂停中仍响应继续、保存与停止。

暂停意图在 `<run>/workbench-control.json`，保存队列在 `<run>/workbench-save-requests/<UUID>.json`。两者分别记录，避免覆盖。请求绑定协议版本、run ID 和请求 ID；保存完成后写持久 receipt，重复同 ID 不重复保存。HTTP 接受只表示已排队。运行终止时未处理请求转失败，界面不会永远等待。

只有状态声明 `workbench_control_protocol=1` 的活动运行启用新控制。旧运行按原计划继续，下一轮才使用新协议。

## checkpoint 与参数

手动快照使用同一模式目录下的独立 snapshot run，保留实际配置、完整参数、导出与数值验证报告，不覆盖原运行的最终报告。固定历史基数加本轮捕获量构成累计；快照重复不重复累计，未知历史仍为未知。

`GET /api/workbench/v1/checkpoint-options?mode=...` 只提供当前验证器认可的最终模型和手动快照；选择时按精确路径再次验证。未完成或未验证的周期目录不能伪装成可续训模型。

跨进程续训恢复网络与观测归一化，优化器重新初始化；接口明确返回 `optimizerRestored=false`。这和同进程暂停不同。

`GET /api/workbench/v1/parameters` 返回字段 schema。允许编辑并行环境、batch、小批次数、展开长度、每批更新、学习率、熵系数、奖励缩放、裁剪范围、梯度上限和评估环境数。完整组合必须通过 batch 可整除等校验。网络结构、动作、归一化策略与身份契约不作为普通参数编辑。

参数只在开始下一轮时生效，训练中锁定。空编辑保留现有默认与五项性能配置继承；先前明确编辑的字段通过 `request.json` 继续继承。`ppo_config.json` 与真实 Brax 调用应用同一结果，二者不一致时拒绝训练。现有 runtime preset、原生评估、阶段缓存和计时保持原合同。

## 预览与加载

最多四个独立 CPU 仿真实例，共享总渲染预算。它们展示按打开时捕获的策略运行的结果，不代表全部并行训练环境。每次打开同步一次，查看期间固定版本。关闭或移除释放资源；迟到的同步、环境构建和首帧不会恢复已关闭视窗。

本机真实四窗验收约为每窗 2 FPS，首轮环境编译需要等待。界面持续显示实际阶段；首帧图像请求失败会结束等待并提供重试，不无限显示加载中。

2026-11-15预览修复（2026-11-16已部署）：显示帧率与每视窗播放时钟分开，按单调墙钟间隔推进整数控制步，保留不足一步的余量；单次最多推进0.25秒，丢弃超额积压，避免无限追赶。状态中的`playback_rate`为当前实际推进/活动墙钟间隔，`lag_seconds`为自reset起丢弃的活动播放时间；暂停、无观众、首帧及终态停留不计播放倍率。暂停/断线/关闭重开/reset不补闲置时间。共享20 JPEG/s预算只对实际新绘制帧计费，无观众槽位与暂停缓存不拖低其他视窗刷新率。相同姿态、相机和绘图配置复用JPEG，reset或配置变化重绘；新观众立即获取缓存帧，暂停流每秒发送同一JPEG保活，不重绘编码。这些行为通过CPU合成时钟和调用计数验证；本轮另确认真实暂停帧计数保持，不代表已建立稳定四窗FPS或训练干扰结论。

2026-11-16显示优化（已部署）：共享工作线程按有观众且未关闭的视窗数选择绘图尺寸，暂停但仍显示的窗口也计入布局。已关闭或没有客户端的槽位不降低其他窗口的清晰度。

| 有观众的视窗数 | 每窗绘图尺寸 |
| --- | --- |
| 1 | 800×500 |
| 2 | 640×400 |
| 3–4 | 400×250 |

预览关闭阴影和反射，JPEG质量仍为80。尺寸变化在持有绘图资源的工作线程上替换并关闭旧Renderer，只使图像缓存失效；策略、物理状态、相机、动作历史、控制dt和回合不重置。状态中的`render_width`、`render_height`和`render_effects`报告实际完成帧的配置，首帧之前为null。其他绘图标志仍参与暂停帧失效；场景更新后再次施加低开销效果设置。

部署以实时生产快照为基线，仅两份预览模块变化，保留训练实验及其他发布字节。实际Linux候选34项回归通过，正式8095真实JPEG验收覆盖1→4→2→1窗尺寸切换、无阴影反射及暂停不重绘，结束关闭新增预览。短时启动/切换采样不能证明稳定FPS提升；本轮无活跃训练，未测试训练吞吐或干扰。未切换物理后端或渲染设备，模型与训练源码指纹不变。当前本地主线仍含未部署训练实验，不得直接复制整目录。用户已完成实际验收并授权提交推送。

首次连接与重连集中在导航的小型状态点和文字提示。训练准备、模型同步、环境载入和首帧等待显示实际阶段；只有生产者提供有效分子与分母时才展示百分比，其余使用不定加载条。加载动画和训练进度分别表达，不能用动画推算训练量。

`GET/POST /api/workbench/v1/viewports` 管理视窗；流地址为 `/stream.mjpg?viewport=<id>`。保留旧单窗控制和页面回退入口。

前端附带 `generation` 绑定每次打开；旧代次请求返回409，已有旧流在代次变化后结束。带 `mode` 的能力查询由集成控制适配处理，不能直接交给不接收该参数的独立只读router。

## 目录与导入

`GET/POST /api/workbench/v1/storage` 读取或设置后续运行保存根。旧保存根继续登记供历史查找。活动训练不能更换位置；不迁移正在写入的文件。

Windows 本机桥接 `/api/local/directories` 提供原生选择、打开和取消。打开前先由目标后端验证登记目录；路径作为 argv 传递，不执行拼接的命令。桥接核对目标 WSL 发行版，避免把目录打开到其他发行版。

`POST /api/workbench/v1/import` 完整复制所选已验证 checkpoint 及所需配置到独立导入库，在暂存目录验证后原子发布。保留 checkpoint 身份和历史绑定，重定位实际文件路径；重复导入幂等，失败只清理该次暂存。缺报告、内容变化、链接、越界、容量超限或不兼容产物明确拒绝。

## 模块接点

| 模块 | 职责 |
| --- | --- |
| `workbench_runtime.py`、`timed_console_train.py` | 安全边界、暂停计时、完整快照、真实参数落地 |
| `training_control.py` | 单任务管理、请求身份、能力、精确模型选择 |
| `workbench_parameters.py` | 可编辑 schema、继承和组合校验，不导入模拟器 |
| `workbench_storage.py` | 保存根登记、完整导入、目录授权 |
| `workbench_preview.py`、`hybrid_web.py` | 独立视窗生命周期、共享同步、加载阶段 |
| `tenny/local_directories.py`、`tenny/proxy.py` | Windows 原生目录桥接与同源转发 |
| `workbench-ui` | 能力驱动的交互、真实/不定加载与渐进披露 |

训练核心、物理、奖励、动作映射与模型指纹保持独立。未来替换机器人仍需完整语义契约及实际第二实现；界面允许配置并不等于旧策略能直接控制新机构。

## 状态读取与重连

高频状态/历史列表复用已验证结果，源文件、参考模型、checkpoint、配置或目录变化即失效。签名包含类型、大小、mtime、ctime、inode及链接计数；链接、特殊文件、异常扫描或持续变化不复用缓存。缓存只服务读取，开始续训、精确选择、导入和保存模型预览仍完整验证。

前端一条监督器心跳和一条辅助请求通道，最多两个API连接；四个MJPEG窗口仍为状态留槽。辅助数据逐项到达，不阻塞下一次状态读取。POST仅尝试一次，完成后获取提交之后开始的新心跳。

`snapshot.connection` 区分connecting、connected、reconnecting、offline，并提供失败次数、最后成功时间、原因与下一次重试时间。单次心跳失败即禁用写入，前两次失败显示正在重连，连续第三次起显示离线；重试退避至多8秒。技术details只放折叠详情，不用原始AbortError作主界面提示。导航使用单一连接提示及文字重试，遵守reduced-motion，不按每次轮询重复播报或移焦。

状态连接与训练阶段独立。断线保留最后报告，已工作的同版本视频流保持；离线关闭只移除本地客户端，恢复不自动重开。没有遮挡预览的错误浮层。

本机修复前状态约1.16秒、五路并发最慢5.72秒；缓存建立后约36毫秒/80毫秒。正式45次采样0失败、中位43毫秒/max119毫秒。冷首次完整校验仍可能数秒，这些有限样本不构成永久网络可用性保证。

## 发布与验收

正式入口保持本机8095，指向独立版本网页服务。固定Windows桥接副本不依赖临时Worktree；WSL版本记录与 `workbench-current.json` 包含精确源码清单、启动参数、进程和previous回退信息。测试产物位于该版本独立acceptance根，不参与生产latest选择。

模型包根在已解析参数的monitor创建入口确定，早于teacher/hybrid生命周期分派。这样版本化外围与固定模型源码不会交叉缓存不同XML根；严格校准守卫与模型指纹保留。

真实隔离GPU验收覆盖暂停、暂停中完整快照、同进程继续及停止保存；512配置、实际学习率、原生评估和累计进度均核对。隔离浏览器覆盖参数、模型起点、控制回执、加载/失败/取消及目录入口；正式入口确认真实四窗、单窗独立暂停与最终关闭状态。验收阶段与有限性能样本见[生产整合](workbench-production.md)；精确机器位置和回退参数由部署环境的版本记录保存。
