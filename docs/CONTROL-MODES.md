# 网页训练控制台

在项目根目录运行 `python tenny.py run web`（或在 `python tenny.py` 网页里点“训练控制台”）打开同一控制台。默认首次使用原版，之后记住所选模式；网页连接地址由启动器打印。当前WSL地址在重启后可能变化。

## 直接在网页控制训练

1. 选择原版（腿位置＋轮速度100Hz）或全扭矩200Hz。
2. 选择定时并填写分钟数，或选择不限时。
3. 点击“开始新训练”，从随机初始化开始；已有结果保留。
4. 点击“停止并保存”，等待当前计算段结束，再完成保存、重载和导出验证。
5. 可随时“开启画面并同步”查看当前策略；保存结束后可“从最近模型继续”。

关闭或刷新网页不停止后台训练；再次打开即可恢复查看和控制。训练与保存期间不能切换模式或重复开始。只有训练进程实际退出后才解除锁定。停止是协作式的：如果GPU正在编译、采样或评估，需要等待该段返回；界面会显示停止/保存状态。定时预算包含初始化、编译及评估，最终保存验证单独收尾，存在一个当前计算段的时间偏差。准备阶段过早停止可能还未生成模型，界面会明确标记取消。

“从最近模型继续”恢复该模式最近一次控制台训练中已验证的网络、价值网络和观测归一化参数，优化器重新初始化；不宣称完整优化器无缝恢复。若没有已验证的控制台模型，该按钮禁用。两模式互不混用权重。曲线按本轮步数从零开始，最多显示最近2000点；完整事件保留在metrics.jsonl。

## 展示与训练独立

画面默认关闭。每次从关闭切换到“开启画面并同步”，只请求一次当前最新策略，等训练完成当前计算段后加载；页面显示同步等待、模型来源、本轮步数和同步时间。观看期间固定这一版本，重复开启、暂停/继续、重置回合都不会请求新参数。关闭停止展示推理/仿真/渲染，若仍在等待则取消请求；再次打开重新同步。训练和曲线继续运行。

同步只原子替换约28KB的临时actor参数包（preview-policy.npz，含观测归一化），不保存价值网络或训练检查点，不触发完整导出验证，也没有新增定时同步。现有每300秒/结束保存规则独立保留。训练没有运行时，打开自动加载最近已验证的保存模型；没有控制台模型则沿用明确标注的基线。它仍是独立演示环境，不是挑选训练环境中的最好表现。

功能更新前已经启动的训练进程不支持新请求协议；页面明确提示，下次开始或继续训练生效，不强行中断正在进行的训练。

## 固定训练配置

| 设置 | 原版 | 全扭矩实验 |
|---|---|---|
| 环境 | 原腿位置＋轮速度控制 | 四路绝对扭矩 |
| 控制频率 / actor观测 | 100Hz / 26维 | 200Hz / 24维 |
| 并行环境 | 128 | 128 |
| batch / minibatches | 8 / 16 | 128 / 1 |
| rollout / 每批更新 | 75 / 4 | 16 / 1 |

原版保留原环境、奖励、观测、网络、学习率等，沿用正式PPO的rollout75、minibatches16和updates4，仅将batch512缩小为8以适配本机。全扭矩沿用先前128环境实验配置。Actor64×64、Critic512×4、学习率1e-4、reward_scaling0.1、entropy0.01和0.5秒折扣半衰期保持既有设置。2个真实评估环境约每45秒评估一次；两种loss按训练区间记录，不填造缺失评估。每300秒保存检查点，结束时立即保存和验证。

## 保存与入口

结果位于WSL ~/projects/tenny-torque200/artifacts/console/<模式>/<运行ID>/。网页“保存位置与继续训练说明”显示当前路径。每轮包含request.json、env_config.json、ppo_config.json、status.json、progress.json、metrics.jsonl、train.log、checkpoint、CPU参数快照、policy.cpp.txt及report.json。只有保存验证通过的检查点才允许继续训练；按需预览可以使用本轮尚未保存的策略快照，两者在页面上注明来源。

原版参考源码及作者权重不改。开发诊断入口见 `python tenny.py list` 的“测试”分组，已不作为日常训练入口。旧15分钟训练和性能记录独立保留。
