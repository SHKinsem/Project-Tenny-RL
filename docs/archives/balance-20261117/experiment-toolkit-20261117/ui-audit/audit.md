## 体验判断

- 当前“查看旧模型 → 确认兼容 → 续训”有明确安全边界（精确路径、已验证、不会偷偷替换为最新）；但需要 2 层面板和长路径文本，缺少本实验所需的完整初始化语义及优化器重建的显著提示。
- PPO 参数的作用时机写得清楚：仅已编辑字段覆盖自动/模型配置，并在下一轮一同提交。这对单次手动试验好用；但在对照实验中不够，因为没有配置快照、批次 ID、seed 或变更摘要。
- 图表只提供总 reward、时长、value loss、policy loss；可读性可接受，但不能回答实验最常问的“哪一个奖励项/真实运动量导致差异”。

## 建议

### P0：让最近实验可以在网页上被安全复现和比较

1. 增加“实验矩阵”草稿：一个成熟模型完整初始化、seed 列表、固定步数/阶段、只允许一个可见变量组；提交前显示逐 run 的不可变参数与 descriptor/source fingerprint。
2. 增加 reward 配置卡和曲线：显示每一项数值、XY/轮角权重及运行时生效版本；曲线至少含真实 `x/y` 位移、机体姿态、轮角/轮速，而不是只有总回报。
3. 增加评估合同卡：固定 120 s、5 个命名初态、同模型/同初态配对；运行后提供每 case 曲线和成组 JSON/HTML 报告链接。

### P1：让已有 checkpoint 能成为实验资产

1. 历史模型列表增加“完整 checkpoint / 自动保存 stage / 指标摘要 / 最佳原因”，并可按 run、步数、配置指纹筛选；保留精确路径和兼容验证。
2. 在“续训”确认前固定展示：网络、归一化、优化器是否恢复、五项继承配置、源指纹和差异；把目前藏在帮助文本的“下一轮提交”做成变更摘要。
3. 运行描述必须补齐 robot/model/task 身份，显示 input freeze 和源码/descriptor hash；“未记录/未报告”应成为警告而非静默字段。
