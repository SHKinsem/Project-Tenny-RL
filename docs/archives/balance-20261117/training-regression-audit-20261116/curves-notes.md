# 六次训练曲线审计

**范围仅限六次从共同bootstrap BC初始化出发的配对短训。没有检查用户此前已经正常平衡、仅有轻微漂移的成熟模型，也没有执行该成熟模型的低学习率位置保持微调；以下结果不能外推为该路线无效。**

只读既有记录。共同0步的三初态确定性6秒回报为10568.942344；六次最终回报全部更低，因而现有曲线不支持“训练把原回报提高，却牺牲原地站立”的整体解释。

## 采样口径

- progress每run仅5点：0、524288、1048576、1572864、2097152环境步；每点是3个固定主要初态、6秒上限的确定性原生评价，不是随机训练回合收益。训练回合本身为30秒。
- training-metrics每run仅4个段末点，没有0步loss/std。保存loss、熵损失、KL和分布loc/std统计；未保存训练episode回报/长度、reward分项、clip fraction或梯度范数。未采样不能填零。
- 全部normalizer漂移0；各采样actor哈希改变，最终status确认actor有更新和重载精确。

## 学习率与标准化

六run的PPO配置learning_rate均为3e-5，未设置learning_rate_schedule。24个实际日志采样只有一个值：2.9999999242136255e-05，是3e-5的float32表示，不是动态衰减。

实际安装Brax源码已按保护SHA核验：train的learning_rate_schedule默认None，选择LRSchedule.NONE，Adam直接接收常数learning_rate；自适应KL分支存在但本轮未启用。源码内没有对learning_rate参数重新赋值。

PPO标准化为EMA、normalize_until_count=0、std_eps=0；所有过程采样normalizer_drift=0。它不是随着训练继续拟合观测统计的设置。

## Snapshot与缺失证据

实际冻结源码tar中的reward_ablation/train.py已与runtime-freeze SHA核对一致：398bc1a151e47d8df566621417ea777914659d9d957d3450c79ff33ceb1ef356。过程回调记录5次哈希、写latest-descriptor.json并覆盖；checkpoint只在train返回后保存一次，PPO配置save_checkpoint_path=null。Windows每run仅归档progress/training-metrics/effective-config/status四文件，没有中间权重。没有穷举WSL额外人工产物。

因此可做0步与最终策略的奖励分项/回放诊断，但仅靠目前归档无法回放524288/1048576/1572864步策略，也不能将首次下降精确归因于某项reward/某次更新。训练随机rollout实际回报未记录，确定性回报下降也不等于已证明PPO在优化过程中没有提高其采样目标。

配置仍为lr3e-5、entropy_cost=.001、max_grad_norm=1、gamma=.9862327045（奖励折扣半衰期.5秒）、lambda=.9025、unroll16（.16秒）。这些短时间尺度可列为后续受控诊断问题，现有曲线不能证明它们就是退化根因。

一次解析与输入核对主体0.281秒，读取的28份输入SHA均未变；未启动训练、评估或模型加载。详细每步字段与未采样标记见curves-summary.json。
