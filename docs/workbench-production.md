# 工作台生产整合与运行边界

2026-11-15 更新。正式入口为本机 **http://127.0.0.1:8095/**，`/legacy` 保留旧页面。网页及外围模块从独立发布版本运行，Windows 桥接使用固定发布副本，不依赖临时 Worktree。当前 run、checkpoint 和进程状态由真实监督器提供，部署清单保存各次发布时的值。

## 当前已接通的行为

- 极简工作台读取真实监督器、学习曲线、checkpoint 属性、参数与 MJPEG；保留三栏拉伸、阈值折叠、子组折叠、动效及 24px 参数缩进。
- 支持新训练、最新或精确历史模型续训、停止并保存、模式切换。历史起点必须通过实际兼容性验证，提交所选精确路径。
- 活动进程声明 `workbench_control_protocol=1` 时，支持安全边界暂停/原位继续与独立完整快照。旧运行按原计划继续，不为增加能力重启。HTTP 接受仅表示请求排队，保存完成看持久回执。
- 并行、PPO 和评估的 11 项参数由 schema 提供；训练中锁定，仅下一轮应用。只提交编辑项，空对象保留自动默认与继承配置，实际 Brax 设置和保存记录一致。
- 至多四个独立 CPU 预览，各自开启、暂停、重置与释放；每次打开同步一次，查看期间固定版本。真实四窗验收约每窗 2 FPS，首次环境编译仍需等待。
- Windows 原生桥接提供目录选择、打开和取消；后端登记后续保存根、校验目标发行版，并对导入模型完整复制、验证、原子发布。活动训练位置不可改变。
- checkpoint 旁路及运行起点已接到真实保存包装层；固定父基数加实际捕获量，最终采用训练截止量，暂停与最终保存耗时按合同分离。旧历史未知保持 null。
- 导航使用持久 UUID 短形式，详情保留完整身份和本轮捕获量；不按排序分配编号，不用累计步数改写权重目录名。

跨进程续训恢复网络与观测归一化，优化器重新建立；同进程暂停保留优化器。这两种恢复方式的能力不同，接口返回真实恢复语义。完整控制及目录合同见[控制、保存与加载](workbench-controls.md)。

## 采样与连接状态

评估与 loss 独立采样。`learning-data.points[].measured` 标记当前回调真正采样的指标；未采样事件不切断其他指标，显式无效值保留断点。末尾空回调不覆盖实际最新测量。首批真实窗口的 343 条回调中只有 3 个评估点，界面按实际口径分别显示。

连接提示集中在导航的小型状态与文字重试，技术错误只进入折叠详情。单次心跳失败即禁用训练写入，训练阶段与数据保留最近报告；已有同模式/模型运行/代次的健康视频流继续使用，离线手动关闭只移除本地客户端，恢复后不自动开启。

监督器心跳与辅助数据分开调度，辅助数据不阻塞下一次状态读取。读取缓存按源文件、产物及参考模型变化失效；启动续训、精确模型选择、导入与模型预览仍执行严格验证。

重连修复后的正式入口连续 45 次状态采样无失败，中位 43ms、最大 119ms。该记录反映当次环境；冷首次完整校验仍可能数秒，不构成永久可用性保证。

## 训练加速与恢复限制

整合以实际已部署的腿力 v3 为基准，保留以下能力：

- 新腿力训练默认 512 环境、batch 512；续训继承模型原有五项批量设置，显式编辑项按已保存请求继续继承。
- 已接入的腿力模式使用原生 C++ 评估；其他模式沿用其后端选择。
- 保留原有阶段计时、持久编译缓存、准备缓存及打开预览时单次同步。

物理、动作映射、奖励、网络定义与受保护模型源指纹保持独立。可编辑配置通过外围 schema 校验后作用于真实训练，不修改正在运行的参数。

首批整合的独立 30 秒预算续训在约 30.066 秒截止，完成 458752 步；auto 继承 512 设置、实际 Brax 配置、原生评估与元数据发布一致。该验收总墙钟约 43.03 秒，产物位于独立 acceptance 根，未晋级生产 latest。这是历史接线验证，不能据此得出速度因果对照或收敛结论。

后续真实隔离验收已覆盖暂停、暂停中完整快照、同进程继续及停止保存，并核对 512 配置、学习率、原生评估与累计进度。旧模型没有可靠历史时仍返回 null，不能从文件名或读盘时间补造。

## 模块边界

| 模块 | 职责 |
| --- | --- |
| `workbench-ui/adapter.mjs` | 数据转为视图语义，分离存活、连接新鲜度、累计量及采样缺口 |
| `workbench-ui/transport.mjs` | 同源心跳与辅助通道、重试、请求新鲜度；独立于机器人算法 |
| `workbench_web.py` | 静态白名单与集成 API 接合，不进入训练算法 |
| `workbench_api/reader.py` | 受限产物读取、来源/revision 和保存描述，不实例化训练管理器 |
| `checkpoint_metadata.py`、`workbench_persistence.py` | 版本化累计计算、固定起点与捕获旁路的原子发布 |
| `workbench_runtime.py`、`timed_console_train.py` | 安全回调控制、暂停计时、完整快照及真实参数应用 |
| `workbench_parameters.py`、`runtime_defaults.py` | 有界字段及组合校验、自动默认和续训配置继承 |
| `workbench_preview.py` | 独立预览生命周期、加载阶段、代次与资源释放 |
| `workbench_storage.py` | 保存根登记、完整导入与目录授权 |
| `tenny/local_directories.py`、`tenny/proxy.py` | Windows 原生目录桥接及固定同源上游 |

模式、频率和名称来自后端 catalog；descriptor 从保存的 policy/env/PPO 提供身份、观测版本、动作顺序与运行配置。未记录身份或单位为 null，遥测按实际数组渲染，不从相同维数推断兼容。

未来替换机器人仍需完整 robot/task/action/policy/runtime 语义：身份与版本、坐标与正方向、绝对或增量、缩放与限幅、历史更新顺序，以及实际第二机构验收。原机器人的内部索引、几何映射、观测、奖励和重置尚未全部通用化。

## 验收、发布与回退

仓库的 Git 属性保留受保护源码及资产的实际部署字节，包括既有 LF/CRLF；不要批量转换或格式化这些文件。提交阶段已按 59 个指纹输入核对 Git 对象与部署基线一致，避免源码内容相同但换行变化导致旧 checkpoint 被拒绝。部署记录和物理模型指纹仍是兼容判断依据。

- 读取/元数据/HTTP、运行配置/计时/原生选择、旧控制台兼容、目录桥接和前端状态/传输回归已通过；早期测试批次数保留在[后端说明](workbench-backend.md)。
- 隔离浏览器验收覆盖参数草稿、精确起点、暂停/继续、保存回执、目录入口及加载/失败/取消；正式入口确认真实模型、曲线、四窗和单窗独立暂停，结束后关闭新增预览。
- 重连隔离验收覆盖状态失败/恢复、四个健康 src 保留、本地关闭不发 POST、恢复不自开；另提供 390 CSS 像素窄屏入口用于布局复核。正式入口随后刷新验收，并完成上述 45 次状态采样。
- 发布证据和精确机器位置记录于部署环境的清单，测试产物位于版本独立 acceptance 根，不参与生产 latest 选择。公开文档仅使用可移植引用。
- WSL 备份按产物根下 `workbench-upgrade/<release>/` 管理；固定桥接与网页发布副本的位置由版本记录及 `workbench-current.json` 提供。
- 回退先核对活动训练，再按清单恢复对应非指纹文件与静态资源，使用已记录 argv/env 重启网页服务；桥接使用 previous 记录恢复。避免整目录覆盖并行改动或重启 WSL。

接口总览见[后端能力](workbench-backend.md)，累计格式见[checkpoint 合同](checkpoint-progress.md)。后续发布以实际运行版本和变动清单为基准。
