# 网络结构搜索计划（policy 受限 / value 自由）

> 目标：在**不增加端侧 policy 计算量**的前提下搜索 policy 网络结构；
> value 网络只在训练时使用，可自由修改。
> 本文档只给计划，不改动任何代码。

## 1. 现状盘点

### 1.1 当前网络（代码默认值，`legwheel/training/ppo.py` `curriculum_learning`）

| 网络 | 输入维 | 隐藏层 | 输出维 | 说明 |
| --- | --- | --- | --- | --- |
| policy | 26（`state`） | [64, 64] | 8（4 动作 × mean/log_std） | 端上部署，100 Hz 推理 |
| value | 55（`privileged_state`） | [512, 512, 512, 512] | 1 | 仅训练用，端侧不部署 |

- policy 结构即已部署策略 20260111-2109 的形态（`deploy/params.cpp.txt` 中 26×64 / 64×64 / 64×8 三组权重可证）。
- `get_ppo_config` 里的 (128,128)/(128,128) 是占位值，实际被 `curriculum_learning` 的 [64,64] 与 [512]×4 覆盖。
- 观测维 26、动作维 4 由环境与固件观测/动作管线决定，**本轮不动**。

### 1.2 policy 计算量预算（硬约束）

以 MAC（乘加）计，每次前向：

| 层 | 计算 | MACs |
| --- | --- | --- |
| 26→64 | 26×64 | 1664 |
| 64→64 | 64×64 | 4096 |
| 64→8 | 64×8 | 512 |
| **合计** | | **6272 MACs ≈ 12.5 kFLOPs** |

- 100 Hz 下约 1.25 MFLOPs/s，参数总量 6408。
- **硬约束：候选 policy 每次前向 MACs ≤ 6272，参数量 ≤ ~6.5k。**
- 激活函数、观测归一化由固件前向代码决定，不在本轮搜索范围内（只搜层数/宽度）。

## 2. policy 候选结构（全部满足 MACs ≤ 6272）

| 编号 | 结构 | MACs | 参数量 | 设计意图 |
| --- | --- | --- | --- | --- |
| A0 | [64, 64]（baseline） | 6272 | 6408 | 现状，对照组 |
| P1 | [128] | 4352 | 4488 | 单层加宽，最少深度最快推理 |
| P2 | [160] | 5440 | 5608 | 单层进一步加宽 |
| P3 | [176] | 5984 | 6248 | 预算内单层最宽 |
| P4 | [48, 48] | 3936 | 4080 | 双层变窄，验证宽度冗余 |
| P5 | [56, 56] | 5040 | 5264 | 双层略窄 |
| P6 | [48, 48, 48] | 6240 | 6448 | 预算内最深（3 层），验证深度收益 |
| P7 | [64, 32, 64] | 6272 | 6208 | 瓶颈结构，压缩-重建表示 |

说明：

- MACs 相同不代表端侧耗时相同——层数多会带来更多次 kernel 调用开销，单层/双层在 MCU 上通常更划算；排序时同分优先浅层。
- 观测 26 维中有明确弱信息维（如大腿速度维喂纯噪声），单层宽网络可能已足够，这是 P1–P3 存在的理由。
- 3 层候选只有 P6/P7 两种能进预算，再多层必然超支，不列。

## 3. value 候选结构（自由，仅影响训练）

policy 搜索期间 value 固定 [512]×4；policy 定稿后用最优 policy 再扫 value：

| 编号 | 结构 | MACs | 说明 |
| --- | --- | --- | --- |
| V0 | [512, 512, 512, 512]（baseline） | ~815k | 现状 |
| V1 | [1024, 1024] | ~1.1M | 加宽减深，训练吞吐更好 |
| V2 | [1024]×4 | ~3.2M | 容量上限试探 |
| V3 | [512]×6 | ~1.3M | 加深 |
| V4 | [256, 256] | ~80k | 反向验证 value 是否已过剩 |

- value 只在 GPU 训练时用，加大容量代价是训练吞吐下降，需在结果表中记录 SPS（steps/s）变化。

## 4. 实验协议（沿用 run2 收官时定下的铁律）

1. **σ / sigma_wheel 固定 0.5**，不进任何搜索。
2. **评测口径只用 deploy 口径**：deterministic 策略 + 域随机化 + push + 噪声 + 固定 σ=0.5；报表口径只做训练仪表板。
3. **打分用无权重 reward 和**（8 项达成率之和 − action_rate），越高越好；RMSE 不单独作指标。
4. **两阶段**：
   - 初筛：每个候选 1e8 steps × 2 seeds，deploy 口径单点评测；
   - 确认：初筛前 3 名跑 4e8 × 3 seeds，deploy 口径逐 ckpt 实测曲线。
   - 注意：1e8 排名反转已有三次先例（base2 RMSE、cand026 sinyaw、006），**任何结论必须以 4e8 确认轮为准**。
5. policy 搜索时其余训练参数全部锁 baseline（lr 1e-4、updates 4、kp 2e-4、notsmoothing 0.5、9 项权重、half_life_s 0.5 等），只改 `policy_hidden_layer_sizes`。
6. value 搜索时 policy 锁 policy 阶段的最优结构，只改 `value_hidden_layer_sizes`。
7. 训练纪律不变：`.venv-local/bin/python`、`CUDA_VISIBLE_DEVICES=N`、`XLA_PYTHON_CLIENT_MEM_FRACTION=0.1`、GPU 用量进 log。

## 5. 结果产物

- 初筛：候选 × seed 的 deploy 口径无权重和排名表（1e8）。
- 确认：4e8 全表 + 逐 ckpt 无权重和曲线（对照 A0 baseline）。
- 结论：推荐 policy 结构 + value 结构，附 MACs/参数量/SPS 对照，确认端侧预算未超。
- 汇总文档：`docs/network_structure_results.md`（实验跑完后生成）。

## 6. 风险与注意

- 改 policy 结构后旧 ckpt 不兼容，确认轮全部从头训。
- `legwheel/deployment/extract.py` 按层遍历导出参数，层数变化可自动适配，但端侧固件前向代码需同步改层配置——**结论若改结构，需提醒固件侧同步**。
- 若所有候选都不优于 A0，结论就是"保持 [64,64]"，这也是有效结论。
