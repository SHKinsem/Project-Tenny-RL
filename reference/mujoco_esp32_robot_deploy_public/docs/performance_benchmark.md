# 真机控制耗时与优化记录

## 测量方法

为避免漏掉神经网络和调试路径，测量采用以下统一口径：

- 设置 `run_interval=1`，确保每次 `Control::compute()` 都触发神经网络。
- 每秒汇总所有调用，而不是每秒只取一个样本。
- 输出平均耗时、最大耗时、调用次数和微秒级直方图。
- 分项测量时，模型通过独立前向计算入口计时，不产生电机动作；测量完成后关闭该入口。
- 测试结束后恢复 `run_interval=4`，最终固件不额外执行模型。

相关统计代码位于 `wl_pro_robot.ino`，模型分项计时位于 `src/control/control.cpp` 和 `src/control/control.h`。

## 优化前后总体对比

| 指标 | 优化前 | 优化后 |
|---|---:|---:|
| 加权平均 `compute()` 耗时 | 776.6µs | 785.6µs |
| 最大耗时 | 10,108µs | 1,889µs |
| 平均耗时变化 | — | 约 +1.2% |
| 峰值降低 | — | 约 81% |

神经网络主导平均耗时，因此约 1% 的平均值波动没有实质意义。主要收益是消除调试字符串产生的耗时尖峰。

优化内容：

- 移除控制循环中的 `VectorXf::Zero()` 重复分配，改为初始化时分配一次。
- 调试输出改为真正按周期执行，避免同一毫秒内重复生成。
- 周期调试只保留时间、耗时、电池和双锚点状态，不再拼接全部参数与传感器数组。
- 为调试字符串预留空间，页面字符串按只读引用返回。

## 优化版耗时分布

测试条件为 `run_interval=1`，共采集 2114 次完整调用：

| 耗时范围 | 调用次数 | 占比 |
|---|---:|---:|
| `<100µs` | 0 | 0% |
| `100–199µs` | 0 | 0% |
| `200–399µs` | 0 | 0% |
| `400–799µs` | 432 | 20.44% |
| `800–1599µs` | 1677 | 79.33% |
| `1600–3199µs` | 5 | 0.24% |
| `≥3200µs` | 0 | 0% |

绝大多数调用位于 0.4–1.6ms，超过 1.6ms 的调用占 0.24%，本次没有超过 3.2ms 的调用。

## 传感器、模型与其它分项耗时

稳态分项结果：

| 部分 | 平均耗时 | 占比 |
|---|---:|---:|
| 传感器读取 `get_sensors_data()` | 793.6µs | 48.8% |
| 神经网络 `RL_Policy::run()` | 653.0µs | 40.2% |
| 其它控制逻辑 | 179.0µs | 11.0% |
| 合计 | 1625.6µs | 100% |

“其它控制逻辑”包括观测拼装、锚点更新、PID、输出映射和调试等。

## 串口统计输出

固件每秒输出以下指标：

- `compute_avg_us`：本秒 `Control::compute()` 平均耗时。
- `compute_max_us`：本秒最大耗时。
- `compute_calls`：本秒调用次数。
- `hist_us`：各耗时区间的调用次数。
- `sensor_avg_us`：传感器读取平均耗时。
- `model_avg_us`：模型前向计算平均耗时。
- `other_avg_us`：总控制耗时减去模型耗时。

独立模型计时的编译开关为 `BENCHMARK_POLICY`，最终默认设为 `0`，避免给正常控制增加额外负载。

## vx 指令变化率与 ds 突变

### 测量方法

使用同一组“站立→前进→松手”轨迹，比较不限速率以及 `vx_rate=0.2、0.5、1.0、2.0 m/s²`。同时记录滤波后的 `vx` 和停车位置误差 `ds`，并计算松手后的 `|ds_rate|=|Δds/Δt|`。

曲线见 [vx_ds_rate_comparison.png](images/vx_ds_rate_comparison.png)，原始数据见 [vx_ds_rate_comparison.csv](vx_ds_rate_comparison.csv)。

### ds_rate 对比

| `vx_rate` | 最大 `|ds_rate|` | 均方 `ds_rate` |
|---|---:|---:|
| 不限速率 | 19.625 rad/s | 7.889 rad/s |
| **0.2 m/s²** | **0.000 rad/s** | **0.000 rad/s** |
| 0.5 m/s² | 3.621 rad/s | 1.060 rad/s |
| 1.0 m/s² | 9.092 rad/s | 3.510 rad/s |
| 2.0 m/s² | 13.997 rad/s | 6.199 rad/s |

### 结论

- 松手后直接冻结位置锚点会让惯性转化为 `ds`，继而触发反向修正。
- 对全部 `vx` 控制过程施加变化率限制，可以让锚点在减速过程中持续跟随实际运动，避免锚点和实际位置突然分离。
- 本组测试中 `vx_rate=0.2 m/s²` 的 `ds` 和 `ds_rate` 均保持为 0，效果最佳。
- 实验时默认 `0.5 m/s²` 相比不限速率，最大 `ds_rate` 降低约 81.6%，均方 `ds_rate` 降低约 86.6%，但仍有约 0.21 的 `ds` 峰值；当前固件、Web 和仿真回退默认值已统一为效果更好的 `0.2 m/s²`。
- 更大的 `vx_rate` 虽然让指令更快归零，却更容易产生位置误差突变。
