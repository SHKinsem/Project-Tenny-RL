2026-11-16，已记录、暂不实施。用户明确要求先保留方案，后续收到明确恢复指示后再开展D0–D6，包括基线冻结和注册接口接入。目标是在已支持的物理、策略和训练后端内，更换机器人或任务时，只新增或替换相应适配实现及注册配置，共享训练运行模块、保存控制和网页流程保持稳定。

## 1. 完成标准与支持范围

“只替换适配层”以改动范围验收：接入第二机器人或第二任务时，允许改对应适配实现、资源、任务配置及一处静态注册；共享训练运行模块、监督器、checkpoint存储、HTTP流程及通用网页不新增按机器人名分支。

先支持现有MuJoCo/MJX、Brax PPO和MLP策略。现有C++原生评估继续复用。新增RNN、其他RL算法、其他物理引擎或新型界面展示需要相应能力扩展，单独评估；本方案不先搭建任意插件市场、远程代码加载、奖励DSL或通用算法框架。

任务声明所需能力，机器人声明提供的能力，控制与策略声明可接受的语义；组合在构建前验证。换机器人能否保留同一任务，取决于它是否提供该任务需要的状态和控制能力。权重兼容由观测/动作/历史/归一化等合同决定，相同维数不等于可续训。

## 3. 对调用者只提供一个实验入口

网页/CLI与训练监督器只选择实验ID和配置；由一个静态注册入口解析出不可变的`ResolvedExperiment`，再创建所需训练、预览或核验句柄。旧mode保留为旧实验ID的别名，历史路径及参数继续能识别。

拟议的外部Interface只有四类操作，名称可在实施时调整，职责保持：

| 操作 | 输入与输出 | 调用者无需知道 |
| --- | --- | --- |
| `resolve` | 实验ID、配置与运行目的 → 描述和已核对的组合合同 | 包选择、索引、模型路径、观测/动作尺寸如何计算 |
| `prepare_run` | 已解析合同、运行上下文、可选恢复产物 → 可交给训练运行模块的准备结果 | 环境构建、可选教师准备、网络工厂、评估/导出如何选择 |
| `open_preview` | 已解析合同、已验证固定策略、显示选项 → PreviewSession | 机器人相机、策略读取器、物理推进及遥测映射 |
| `validate_artifact` | 产物、已解析合同、用途 → 兼容结果及原因 | 各历史格式、源指纹和动作头校验细节 |

描述查询只读、无需JAX/MuJoCo重导入或构建模型。昂贵准备显式发生在prepare/open阶段，由原有阶段进度和取消协议报告。路径、工作目录、依赖实例和输出根通过固定上下文注入；初始化后不随回调重新解析配置。

训练运行模块保留Brax专用实现，负责采样/PPO、安全计算边界、控制请求、计时和保存调度；不再认识轮腿、`leg_force_bc`、教师包或动作索引。产物存储负责原子发布和哈希，机器人/策略数学核验由适配实现提供。

## 4. 适配层内部分工

这四类Adapter位于实验模块内部的Seam，客户端不逐一拼装或在每步调用它们。

| Adapter | 拥有的知识 | 复用/替换规则 |
| --- | --- | --- |
| RobotAdapter | XML/mesh/物理资产、关节/执行器/传感器名称解析、索引、坐标和单位、能力声明、几何/标定、模型支持的初态操作、默认相机语义 | 换机构时在此提供真实实现与资产；不定义站立奖励或策略网络 |
| TaskAdapter | 命令与目标分布、任务reset/随机化、actor与critic观测、奖励与指标、终止和时限 | 同机器人换站立/速度跟踪等任务在此改动；通过已声明的机器人/控制能力取状态，不直读私有数组偏移 |
| ControlAdapter | 动作单位、绝对/增量/残差含义、尺度/限幅、保持与延迟、内部历史及执行器映射；需要时按每物理子步刷新雅可比 | 力控制、位置伺服或其他映射在此变动；几何由RobotAdapter提供，不复制模型假设到运行模块 |
| PolicyAdapter | actor/critic工厂、分布与输出头、归一化、策略记忆、推理、导出、固定快照读取和数值核对 | 换网络、观测排列、绝对/残差头在此变动；所有训练/评估/导出/网页使用同一语义 |

配置、注册和模块导入在构建阶段完成。MJX热路径编译成JAX纯数组计算，原生热路径使用编译后的Task/Control实现；物理子步内不跨回Python。两种实现共享描述与一致性用例，不要求把同一Python函数强塞给C++。

可选教师初始化由实验适配实现提供准备阶段，普通任务可以直接初始化策略。教师特有私有记忆、采集与DAgger不成为所有机器人都必须实现的接口；已有准备缓存按真实阶段依赖复用。

## 5. 一份共享语义合同

`ResolvedExperiment`一次性确定以下信息，四类适配实现、训练、预览和产物核验共同使用：

- 机器人资产身份、坐标系、正方向、状态能力和执行器语义。
- Task/Control/Policy各自ID、版本及已支持的实现组合。
- actor与critic字段名称、顺序、shape、dtype、单位、可见性、历史堆叠与归一化规则。
- 策略动作与执行器输入分别声明维数、字段、单位、绝对/增量、尺度、限幅和更新顺序；二者维数可以不同。
- 控制周期、物理周期、整数子步、动作保持/延迟、控制历史及reset顺序。
- 奖励/指标定义、任务目标分布、终止与时间截断语义；训练、评估、预览条件分别记录。
- 策略结构、输出头、分布、内部记忆与导出能力；教师可用信息与学生可部署信息分开。
- 可用训练/评估/预览/导出后端及能力；相机目标与遥测字段来自适配描述。

机器人状态按所需能力提供小型特征树：单摆可只提供关节角/速度，移动任务要求机体姿态/速度等能力。构建时解析并固定取值计算，避免引入装满无关空字段的通用状态对象或每步按字符串查找。

执行时，环境状态明确分为物理状态、Task状态、Control历史和随机键；策略参数及全局归一化统计由Policy/训练模块管理。一次控制周期先按合同推进命令/延迟状态，在整数物理子步内计算控制并积分，再按该任务合同计算观测、奖励、终止和历史更新。各旧模式的采样时刻及reset顺序在D0记录后逐项保持，不以抽象层名义统一成另一套数学行为。编译完成的环境仍提供Brax需要的reset/step；共享循环不在每步解析registry或经Python逐层转发。

## 6. 产物身份、续训与缓存

新产物增加独立实验manifest，保存实际解析合同、资产/实现依赖闭包、策略/归一化格式、运行配置、父产物和权重摘要。具体schema编号在实施时冻结；HTTP现有成功响应保持兼容，新增描述字段采用可选/增量扩展。

身份分开核对：

| 身份 | 约束什么 | 典型变动 |
| --- | --- | --- |
| 执行语义身份 | 机器人/观测/动作/控制历史/策略头与归一化、实际执行实现和资产 | 换执行器映射或观测顺序需要重新判定权重可用性 |
| 训练任务身份 | 执行合同及奖励、目标分布、reset/随机化、终止与计时政策 | 改任务不能伪装为原任务的连续训练 |
| 运行配置记录 | 环境数、batch、学习率、预算等实际应用值及来源 | 沿用已有512默认和checkpoint五字段继承，记录显式覆盖 |
| 准备阶段身份 | 采集、BC、门禁各自实际依赖和上游产物摘要 | PPO独有参数不重复采集/拟合；DAgger绑定父策略和父数据 |

网页排版、传输或读取适配的修改不进入模型数学身份；能改变推理、观测、控制或任务行为的实现必须进入相应依赖闭包。运行模块本身仍记录代码/环境身份供审计，不用宽泛“整个仓库hash”代替阶段依赖。

严格续训使用匹配的执行/任务合同及已有恢复语义。显式warm start另记为新运行和迁移来源，逐项声明可恢复的actor/critic/归一化/记忆/优化器；维数相同或文件能加载不能作为兼容证据。跨进程优化器重建的现有边界继续如实保留。

## 7. 保护旧训练与现有网页

旧实现先通过LegacyAdapter包裹，保留其受保护源码、XML、原metadata与源指纹；以部署清单和真实产物为准创建隔离回归基线。适配包装仍需验证归一化、动作头及默认值，不能仅以源码字节未改宣布等价。

通用训练入口与Legacy路径并行存在。当前运行继续用启动时固定的代码和合同，下一轮新运行才选择新适配路径；迁移过程中旧mode、旧checkpoint地址与旧网页流程继续可用。选择经过明确核验的旧身份，新增兼容凭据用旁路保存，不原地改写旧报告、权重或校验摘要。

旧包存在同名`legwheel`及sys.path切换问题：Legacy路径维持进程级隔离和启动时一次选源；新适配实现使用唯一包路径。避免删除sys.modules、热换同名模块或放松XML根守卫。不同机器人预览需要隔离加载上下文和渲染资源，切换网页选择不停止用户正在运行的训练。

网页继续使用当前工作台和路由。catalog/descriptor统一来自注册描述，参数schema、动作与执行器遥测、相机和指标由后端提供。训练暂停、保存、目录导入、累计进度、曲线原值、多窗、资源释放继续走现有模块。移除通用网页路径对固定四路、`root`名称、24/26维和特定策略三层MLP的假设；已有四类PPO图表可保留，任务额外指标通过描述扩展，不为每个机器人复制页面。

原生评估按组合能力选择：支持的Task/Control/Policy使用现有C++核心；暂未有原生适配时明确选择MJX并记录后端。用户显式要求原生但不支持时返回能力错误，不静默改变执行语义。新任务可新增其原生适配，通用执行器不加入机器人分支。

## 8. 分阶段迁移与停点

| 阶段 | 实施内容 | 完成判据 | 保留方式 |
| --- | --- | --- | --- |
| D0 基线 | 明确现有模式与部署源码根、版本/模型/数据合同、当前并行修改；记录观测/动作/时序/默认值和保存样本 | 各代表模式有可核验的冻结输入/输出与旧产物；本地和已部署事实分开 | 不改变用户运行、默认模式或原产物 |
| D1 注册与合同 | 静态registry、ResolvedExperiment、只读descriptor；旧mode到LegacyAdapter映射 | 列举/描述不启动ML，CLI和网页读同一描述；不兼容组合在构建前有明确原因 | 原训练/网页入口继续工作，允许回退旧描述 |
| D2 运行接入 | 通用训练入口通过prepare_run取得环境、Policy、可选准备/评估/保存核验；迁移一种现有腿力模式 | 新入口完成准备、训练回调、暂停/继续/手动快照/停止保存；调用者不再导入teacher/robot包 | 原console源保留作Legacy；默认入口最后再切 |
| D3 物理/任务/控制分离 | 从现有轮腿实现抽出Robot、Task和Control组合；补站立与指令跟踪两任务 | 同机器人换任务只改Task/config；控制映射和每子步历史更新对冻结基线等价 | 逐模式迁移，每模式通过后再开放，失败退回Legacy |
| D4 预览与产物接入 | 新PreviewSession、统一Policy快照/导出核验、相机/遥测/参数描述；接当前工作台 | 新路径训练/固定策略预览/保存导出语义一致；旧HTTP和历史模型仍能读取，通用网页无机器人分支 | 保留旧产物读取和legacy网页回退，支持新旧manifest并存 |
| D5 第二机器人证明 | 在已有单摆资源上增加MJX/Brax训练与网页适配，组合独立任务，不依赖教师初始化 | 新增适配/资源/配置/注册即可贯通短训练→保存重载→导出→网页；原运行模块/HTTP/通用UI不增加特例 | 保留轮腿回归；原生单摆通过仅作已有参考，另验完整新链路 |
| D6 默认切换与后续Tenny | 单独审阅新路径证据和备份后再决定默认/部署；Tenny机械模型、执行器及能力确认后新增适配 | 用户确认实施验收与切换；至少两个机器人/两个任务符合改动范围标准 | 部署单独授权，保留明确回退；硬件/固件不随本方案自动实施 |

建议先实施D0–D1，确认描述能覆盖现有模式再推进D2–D4；D5是证明解耦完成的必要步骤，不能仅靠接口定义或模拟DTO代替。每阶段独立评审，避免整目录重排和一次性替换所有入口。

## 9. 验收与验证预算（未来实施时执行）

| 场景 | 必须证明 |
| --- | --- |
| 现有腿力＋轮扭矩 | 同观测动作、归一化、每子步J*F、奖励/终止、保存重载和导出符合预先固定门槛 |
| 现有腿位置＋轮扭矩/原版模式 | 各自历史、动作/观测维数和执行器语义保留，不能套腿力权重或模板 |
| 同机器人站立↔指令跟踪 | 只替换Task/config；目标、观测、奖励/指标/reset语义明确；运行控制及网页代码保持 |
| 不同维数单摆 | 1路动作、不同actor/critic维数、不同相机/遥测能走同一训练与网页；无需补`if robot == ...` |
| 旧产物与失败路径 | 明确的旧身份可走Legacy；错误资产/单位/观测顺序/策略头即使同维也拒绝；暂停保存、取消和部分失败不丢已完成产物 |
| 修改范围与身份 | 新机器人/任务只新增相应适配和注册；UI变更不使模型失效；执行/任务语义变化触发对应核验 |
| 性能 | 冷构建/JIT、稳态采样/PPO、评估、保存、预览分别计时；无每物理子步Python回调，无隐藏重复预检 |

复用[验证指南](../docs/validation.md)。优先使用冻结样本和CPU合同/回环HTTP测试，按阶段列最小用例集合；常规阶段先设120秒测试进程预算，失败只局部重验，阶段末至多一轮相关回归。文档规划本身不启动测试。

GPU/真实闭环仅在接口稳定、CPU验证通过且用户授权实施后安排：可先为代表轮腿与第二机器人分别设30–60秒短更新预算，同时预先给每次命令包含编译/准备/收尾的总墙钟上限，并逐段归账。总墙钟到限即停止并保存诊断，不为补足训练秒数自动延长或追加轮次。它只验证通路和参数更新，不认证策略收敛。

新旧运行路径的动作/观测/时序应精确相符；物理闭环跨实现容差在运行前固定。若浮点、JIT或运行方式存在自然波动，保留失败和独立重复基线，不能事后放宽门槛。稳态性能对照采用同一策略/配置/工作量，预先约定允许退化范围，发现超预算再决定是否追加测量。

## 10. 接入时允许改哪些内容

| 需求 | 正常改动范围 | 预期保持稳定 |
| --- | --- | --- |
| 相同能力的新机器人 | Robot适配、资产/标定，必要的机器人专用Control实现及注册配置 | 训练生命周期、保存/存储、HTTP、通用网页 |
| 原机器人新任务 | Task适配、任务配置及注册组合 | Robot物理资源、通用运行控制与网页 |
| 新控制方式 | Control实现、ActionSpec及相应策略合同 | 监督器、目录/保存流程、通用展示 |
| 新策略结构/历史 | Policy适配和明确声明支持的后端能力 | Robot/Task数学、通用控制台；不支持的导出/原生后端明确禁用 |
| 新算法或引擎 | 另行设计训练/执行后端能力 | 不承诺单改机器人适配即可支持 |

本方案建议采用“一个外部实验入口＋内部职责明确的适配组合＋现有模块渐进接线”。审阅重点是合同是否覆盖真实差异、Legacy隔离是否可回退，以及第二机器人能否只改允许范围。具体目录重命名、类名和默认切换时点在对应实施阶段再确定。
