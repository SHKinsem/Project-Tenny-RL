# Native evaluator implementation contract

The pure C++ interface is `include/native_eval/runtime.hpp`. It contains no Python objects and no robot assumptions. A task executes one control period with the engine-provided integer physics substep count; its state is per world. The engine owns model/data lifetime, resets, fixed workload, first-episode accounting, cancellation, and traces.

The Python extension is `native_eval._native`. Its constructor is `Evaluator(xml_path, task, policy, physics_dt=0.0)`. `task` has exactly `type` and `config`: types initially `legwheel` and `pendulum`; flat config values map to TaskParameters numbers/flags/strings/vectors/names. Each task rejects unknown or unsupported settings. `policy` is the supported dense MLP descriptor below; unsupported kinds fail at construction.

`policy`: `{type: "mlp", mean: [..], std: [..], layers: [{weights: [[out,input]], bias: [out], activation: "silu"|"relu"|"tanh"|"identity"}], action_size: int, output_activation: "tanh"|"identity", skip_indices?: [int], network_scales?: [float], skip_scales?: [float], skip_transform?: "identity"|"atanh", skip_clip_epsilon?: float}`. MLP math uses float32; task/physics math uses MuJoCo's native precision. No task-specific head indices appear in generic code.

`evaluate(initial_states, options)` accepts a list of per-world dictionaries with optional qpos/qvel/command and extra mapping of numeric vectors. Options: num_envs, rollout_steps, episode_steps, control_dt, seed, trace_worlds. One initial may be explicitly broadcast; otherwise list length must equal num_envs. Missing qpos/qvel use XML defaults; tasks own supported randomization and receive a deterministic world/episode seed. No Python callback executes inside evaluate; the GIL is released.

Results are dictionaries: returns, lengths, terminated, truncated, reasons, resets, traces (list of arrays for each selected world), control_steps, physics_steps, cancelled, wall_seconds. Record pre-action observation/action and raw post-step qpos/qvel/ctrl/xmat/reward/done before automatic reset; xmat has shape [steps, nbody, 3, 3] and preserves MuJoCo's raw derived state without an extra forward pass. Always execute rollout_steps for every world unless cancelled; accumulate only each world's first episode. A task termination wins over a simultaneous time limit; otherwise the time limit is truncation. `cancel()` is native/atomic and keeps partial results honest. Concurrent evaluate calls on one object fail; independent objects are independent.

Results also include `episode_metrics`, a dictionary of arrays shaped [num_envs]. Its reserved `reward` entry equals `returns`; optional native task metrics accumulate with the same first-episode mask, including the terminal step. Task metric names must be nonempty, must exclude `reward`, and must remain identical across all worlds and control steps, with finite per-step values. A cancellation before any completed step leaves only the `reward` entry.

`policy_actions(observations)` returns batched actions without running physics. Read-only properties: nq/nv/nu/nbody, physics_dt, observation_size/action_size, task_name. `capabilities()` advertises schema/version/tasks/MLP activations and stateless deterministic policy support. Do not claim noise, arbitrary networks, or unrestricted task support.

Model XML/assets resolve from the caller's XML path; constructing an evaluator must report missing resources accurately. Build only in WSL ext4 using the existing MuJoCo package headers/library. Keep the binary/build artifacts outside the Windows source and production runtime. The initial implementation uses one native control thread; no misleading thread-count option is exposed.
