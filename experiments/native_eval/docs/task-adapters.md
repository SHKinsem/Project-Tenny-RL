# 任务与策略适配

先读[接口合同](../INTERFACE.md)。纯 C++ 的职责边界以 [runtime.hpp](../include/native_eval/runtime.hpp) 为准。

任务实现 `make_state/reset/observe/advance`。每个 world 有自己的状态；任务拥有控制历史、物理子步内的动作映射、奖励和终止语义。通用执行器拥有 MuJoCo model/data、首回合计账、时间截断和重置。核心不依赖关节名、轮腿索引或固定观测维数。

接入新任务时，先写明观测/动作单位、reset 及随机种子语义和支持参数，再实现一个原生任务 factory，在绑定的任务选择处注册并声明能力。热循环不得调用 Python。复用模型、调度、统计和 trace，不在任务里再写一份评估循环。

单摆实现是最小实例：`cpp/pendulum_task.cpp`，模型在 `tests/fixtures/pendulum.xml`，独立 MuJoCo 数值对照在 `tests/test_runtime.py`。该任务的 3 维观测、1 维动作、单关节拓扑验证了核心没有轮腿假设。新增适配不必修改核心执行逻辑；注册列表和构建源文件列表仍需显式更新。

轮腿实现按名字解析关节/传感器/执行器，并核对 motor、几何和耦合约束。参数和单位只在[轮腿配置合同](../LEGWHEEL-CONFIG.md)维护。`python/native_eval/legwheel.py` 将已验证 run 导出成描述，核对源指纹与导出文件哈希，拒绝未支持的随机化、历史、延迟或观察配置。保存的随机策略头包含均值与分布尺度；确定性导出只保留最后一层的均值行。

通用 MLP 的层尺寸、激活、归一化和输入 skip 都来自描述。轮残差的索引/尺度由轮腿导出器转换成通用 skip 参数，核心不认识“轮”。新策略格式应增加明确的策略适配和独立数学对照；当前能力不包含 RNN、任意计算图或 Python 推理回调。

完成条件：任务边界输入明确拒绝；独立 MuJoCo 对照通过；提前终止、截断、重置历史和 seed 有证据；既有任务回归通过。性能按完整评估调用测量，并把模型建立、首次调用和持续调用分开记录。实际覆盖以[验证记录](../VALIDATION.md)为准。
