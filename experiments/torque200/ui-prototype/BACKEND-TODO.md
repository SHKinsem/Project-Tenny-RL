## 先统一的数据口径

| 概念 | 当前 UI 语义与建议边界 |
| --- | --- |
| 稳定身份 | `run.id`、`checkpoint.id`、`operation.id` 为完整稳定身份；`C023` 为显示别名。不能用数组序号、目录名或别名替代主键。任务编号可以不出现在导航，接口仍需运行身份。 |
| 本轮新增 | `run.elapsedSeconds` 是本轮新增计时，单位秒；`run.steps` 是本轮新增环境步。`durationSeconds` 是本轮追加预算，当前原型以 0 表示不限时，不是累计目标。 |
| 历史与累计 | `baseTrainedSeconds/baseTrainedSteps` 来自父 checkpoint；模型的 `trainedSeconds/trainedSteps` 是累计量。已有 `steps` 字段保持原语义，不据它猜累计历史。 |
| 未知值 | 旧模型未记录的历史时间或步数分别为 `null`，UI 显示“未记录”；不能填 0、按吞吐推算或把另一个字段冒充该值。明确从新策略开始时，已知无历史才为 0。 |
| 计时政策 | 当前 UI/mock 的训练预算计时含编译和评估，准备与终止保存另计，暂停不增长；它不是纯 GPU 计算耗时。后台快照不另加时间，也不打断仍在运行的训练计时。并行生产各模式的实际政策需确认后适配；必须明确 `clockPolicyId` 及各阶段计入规则，再累计兼容口径的历史，不假定生产已统一。 |
| 时间与顺序 | 建议协议时间戳统一为 Unix 毫秒并带服务端时间；持续时间用秒；步数为非负整数。页面读取时间、训练进度更新时间、评估时间、策略捕获时间与校验完成时间分别表示。事件/记录有稳定 ID 和序列，不能只靠客户端到达顺序。 |
| 验证状态 | 写出文件、参数重载/导出校验通过、独立行为评估通过是不同状态；只有对应校验实际完成才发布对应结果。 |
| 当前与草稿 | 当前运行配置不可因编辑控件而改变。模型来源、目录、参数的选择先更新待提交配置，明确 apply/start 后才按协议生效。 |
| 预览 | 预览拥有独立状态与实例身份。打开时捕获一次策略版本，观看期间固定；暂停/关闭预览不暂停训练，暂停训练也不强制关闭预览。 |

### 累计续训验收基准

父 checkpoint `C023` 已记录 600 秒、524288 环境步。追加预算 600 秒时，本轮从 `elapsedSeconds=0/steps=0` 开始，累计为 600 秒、524288 步，计划总时长为 1200 秒，时间进度初始为 **600/1200=50%**。本轮增加 60 秒、81920 步后，累计为 660 秒、606208 步，时间进度为 55%。该进度描述预算消耗，不描述策略质量。

历史时间为 `null` 时，只显示本轮时间进度，不能画出基于未知历史的累计百分比；历史步数可独立为已知或未知。不限时训练不生成虚构的计划总时长或百分比。当前曲线仍使用本轮环境步，不因恢复 checkpoint 自动拼接父运行曲线。

派生比例须区分 `segmentPercent` 与 `cumulativePercent`（单位均为百分数）：前者为本轮 `elapsedSeconds / durationSeconds × 100`，后者为 `(baseTrainedSeconds + elapsedSeconds) / (baseTrainedSeconds + durationSeconds) × 100`。历史未知时累计比例为 `null`，但追加预算为已知正数时仍能显示本轮比例，并明确标“本轮”；预算不限时则两者均没有计划占比。真实新增量和超时不能因进度条显示范围而被截断或改写。

### BE-02：开始、暂停、继续、后台快照与结束保存

- **真实协议需确认或补齐：** 开始操作幂等；安全计算边界暂停/继续；同一运行的恢复；后台快照不终止训练；结束并保存等待安全边界再结束。保存/校验、模式切换和重复开始之间的互斥与排队政策须明确，不能把旧 stop-save 当作 save-and-continue。

- **来源：** D-03 / 历史 B-10；D-06；F-01、F-02。

## 接入前仍需明确的决策

1. 各模式采用哪个计时政策，以及旧累计时间能否与新政策相加；不兼容时保留原口径并说明，不能直接混算。
2. checkpoint 的实际恢复组件与 `resumeKind`；快照请求时刻和实际捕获安全边界的关系。
3. 快照进行中收到结束/再次保存请求时，是明确拒绝还是排队；命令幂等与异常退出后的恢复方式。
4. 短别名的项目命名空间、分配/迁移及跨服务重启稳定性；完整身份始终保留。
5. 参数 apply 的具体生效时点、哪些字段可调，以及目录选择/导入/打开的本机能力与访问范围。
6. 多环境预览实例上限、传输/渲染预算，以及长历史数据查询、缺口和服务端降采样政策。

以上决策先核对并行后端的实际能力，再补齐缺口与适配 UI。本文所有验收示例均为后续实现的目标案例，不代表本轮已在真实服务执行。
