# 训练工作台：本轮改进与设计原则

日期：2026-11-15。范围：本轮独立UI的设计总结；真实训练、渲染与目录能力未接入。

核心方向：**让内容和操作关系建立秩序；默认保持安静，需要时再给出精确的信息和控制。**

当前效果：[桌面](qa/preview-inset-desktop.jpg)、[窄屏](qa/preview-inset-mobile.jpg)。运行入口见 [README](README.md)，后端交接见 [BACKEND-TODO](BACKEND-TODO.md)，可运行行为示例见 [examples](examples/README.md)。

## 这一轮具体改了什么

| 方面 | 原先的问题 | 本轮形成的做法 |
| --- | --- | --- |
| 信息架构 | 状态、配置、画面和指标挤在一起 | 左侧纵排曲线，中间预览，右侧参数；顶部任务/状态/checkpoint，底部训练操作 |
| 区域识别 | 用重复名称和大量边框解释区域 | 删除展开态的“曲线/预览/参数”等自明名称，靠对齐、留白和内容分类 |
| 字体 | 小字过密，随后又出现字号/粗细混杂 | 导航统一14px常规字重；分组、正文、辅助文字保持15/14/12px，底部时间18px |
| 导航 | 内部运行号与占位说明挤占位置 | Tenny、任务和状态在左，checkpoint独立靠右，隐藏R024等内部编号 |
| 曲线 | 大圆点叠成粗线，轴和说明占空间 | 默认无轴细线；标题、尺度控件和精确读数按需出现，无常驻逐点标记 |
| 数据尺度 | 大跨度和微小变化难同时观察 | 线性/正值对数/对称对数；保留原值、缺口和微小数值精度 |
| 读数卡 | 重复指标名、长说明导致卡片过大 | 卡内突出原值，步数和时间并排；非线性尺度简短提示，范围与原因留给尺度控件 |
| 面板布局 | 固定宽度、折叠入口占空间 | 三栏可调宽，拖窄跨阈值收起，窄边拖回展开；使用不同收起/展开阈值避免反复闪动 |
| 折叠控件 | 箭头常驻、纯控件标题行浪费高度 | 箭头默认透明；标题右移和箭头淡入同步，进度区/窗口组/子窗口的控件内置角落 |
| 多窗口 | 单窗反复写“视窗/视窗01” | 单窗不命名，多窗只编号；编号也放角落，不独占横栏 |
| 状态和动效 | 状态表达单调或动效无语义 | 训练小绿点；白色充能扫光表达活动，暂停/失联/过期时关闭；折叠、浮层和布局使用短过渡 |
| 产品文案 | 模拟说明和调试工具混进正常页面 | 正常页面采用正式产品文案；测试控件仅显式dev=1显示，隔离事实留在开发文档 |
| 续训 | 导入旧模型后进度容易从零开始 | 内存模型区分历史累计与本轮新增，10分钟历史+10分钟预算从50%继续，未知历史保留null |

最后一项是已验证的模拟语义，不能当作真实checkpoint后端已完成。

## 可复用的设计原则

### 1. 内容能说明用途，就不重复命名

曲线形态和参数表单已经表达了用途；单窗口也不需要再标“视窗01”。保留能帮助决策的具体指标、参数含义、状态和多窗口编号。

例外：内容收起后，提供简短恢复名称或动作；不能为了删除文字而让用户找不回面板。任务名应可理解并允许用户命名，内部ID不直接当作产品语言。

### 2. 排版承担分类，字形承担主次

先使用一致的网格、边距、行距和留白，再考虑边框。同一层级统一字号与字重；不同阅读任务才拉开层级。

极简界面仍需要易读的正文和清楚的重点。数据线、进度轨道和键盘焦点具有功能意义，可以保留；不要把装饰分割线重新加回来。

### 3. 默认给趋势，交互时给证据

常态只保留细线。移入或聚焦后显示指标名称、原值、步数和时间，再按需查看尺度/范围。卡片不重复父级标题，也不堆叠内部实现说明。

隐藏的是展示层，原始记录、精度、单位和时间语义仍须完整。键盘路径要与鼠标等价；完整触屏等价性仍需专项验证。

### 4. 图表简洁必须以数据诚实为前提

密集数据按显示宽度采样，保留首尾和极值；读数查询完整原始记录。缺失处断线，不能填零、取绝对值或用平滑掩盖波动。

正值大跨度Loss可用对数；零/负值按数据范围选择对称对数，不能强行套正值log。微小值保留科学计数，不能把非零量格式化为0。不同尺度的曲线高度不能直接作为优劣比较。

### 5. 操作不应额外占据一整行

纯为折叠保留的横栏应回收；角落控件使用内部定位，编号可叠放。多层控件需要错开，点击区域不能覆盖时间、读数或按钮。

有实际分类或状态意义的标题可以保留。主面板拖窄收起、窄边拖回、键盘恢复相互配合，至少保留一栏打开，避免出现无法恢复的空工作区。

### 6. 动效解释变化，不能推挤内容

标题用transform平移，箭头用颜色透明度淡入；右侧摘要、行高和后续表单位置保持。浮层只在进入/离开时过渡，逐点滑动不重播入场。

充能扫光只表达正在训练，不改变百分比、累计时间或质量判断。提供减少动态效果退化；本轮实现了退化，但尚未完成浏览器模式验收。

### 7. 颜色只承担少量明确语义

黑白灰承担主体，小绿点只提示确认正在训练；仍保留状态文字。活动、暂停、失联、数据过期和完成的显示必须来自明确状态，不能因旧动画残留而造成误判。

### 8. 界面安静，状态语义仍要完整

历史累计、本轮新增、追加预算、目标总量分别定义；缺失数据保持未知。保存、暂停、停止并保存是不同操作，预览也应绑定固定策略版本。

正常界面不展示开发说明。测试工具和隔离信息放在开发入口与文档中；产品外观不代表服务已接通，更不能把未执行的目录操作写成成功。

## 如何继续验证

先记录小草稿，再实现，再用实际渲染和边界数据核对。当前决策见本文，真实接口待办见 [BACKEND-TODO](BACKEND-TODO.md)；[逐条草稿](../../../tasks/uiux-workbench-draft.md)和 [design-qa](design-qa.md)保留为历史与证据，不把早期规格覆盖回最终界面。

已记录的证据包括1440/900/390视口、真实拖窄及拖回、组/子窗/进度的键盘恢复、一万点/大跨度/正负零/微小变化、累计续训和页面错误日志。精确范围以各QA记录为准。

尚需专项验收：实际鼠标hover的完整路径、连续同一拖动中的阈值微回退、真实触屏、200%缩放/屏幕阅读器、减少动态效果模式与动效逐帧表现。角落控件当前为28px，触屏目标尺寸也需单独评估。

截图前确认视口、页面几何、状态与密度一致；视口切换后的过渡帧不能当作稳定布局。构建/单测通过与真实视觉验收分别记录。真实训练与后端集成保持独立验收。
