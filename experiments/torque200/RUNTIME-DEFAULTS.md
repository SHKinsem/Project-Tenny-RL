# 默认运行配置

已于2026-11-15接入生产并重启控制台。当前腿力教师模式的新训练默认512环境＋batch512，最新保存模型也使用此配置，可直接继续。旧模型自动续训保留其历史并行/批量设置。

## 设置范围

| 项目 | 设置 |
| --- | --- |
| 新的`leg_force_bc`训练 | 512环境、batch512、1 minibatch、1 update、unroll16 |
| 自动续训 | 继承checkpoint原PPO配置中的上述5项 |
| 其他控制模式 | 保留原入口配置；没有外推512性能结论 |
| 评估 | 已接入的腿力模式使用C++原生评估，按当前actor/normalizer执行 |
| 正式训练计时 | 低开销JSONL和阶段汇总；设备profiler仍按需使用 |
| JAX/准备缓存 | 复用现有持久编译及阶段预检缓存 |
| 预览 | 保留打开时同步一次的原行为 |

并行对照的3.28倍只适用于统一batch512的采样/PPO计算，见[实测](../training_profile/SCALING-RESULTS.md)。生产原batch128每8192步4次更新，新配置为1次；完整训练吞吐与学习效果需另行验收。

## 兼容性与单一配置来源

`console_train.py`等原入口属于已保存模型的源码指纹，不为运行性能设置修改其字节。独立`runtime_defaults.py`解析配置，`timed_console_train.py`在最终Brax调用边界应用；PPO JSON、状态和报告使用相同规则。任务观测/动作/奖励、物理控制和网络结构不由这个模块改变。

原入口生成历史兼容模板，模板内128环境断言保留；运行适配层统一生成实际PPO JSON并在Brax入口应用同一组设置。不要只改JSON或只改监控数字。`runtime_profile.json`及report记录`effective_settings`、`applied_to_brax`、来源和配置模块SHA256；实际调用与已保存设置不一致时拒绝训练。

自动续训读取checkpoint所在run的`ppo_config.json`，只继承并行和批量5字段。配置存在但损坏/缺字段时明确失败；整个文件缺失则保留原入口行为并记录`legacy_missing_config`，不伪称恢复了旧参数。

显式选择`throughput512`可用旧权重验证新运行设置，并记录覆盖来源；`legacy`使用原入口值，`checkpoint`要求有完整旧配置。CLI包装入口接受`--runtime-profile`；未指定时读取`TENNY_TRAINING_PROFILE`，默认`auto`。已支持512预设目前仅限`leg_force_bc`。

实际配置和运行模块身份独立留痕，不将性能设置冒充新的控制模型合同。源指纹继续约束原物理/策略代码，输入模型及其元数据不原地改写。

恢复配置校验失败也进入原生命周期的失败处理，保留failed状态、report和计时日志，在进入GPU训练前退出。

## 已启用措施和证据

- **并行配置**：统一批量的128/256/512隔离对照已验证计算吞吐趋势；512候选又完成下面的真实保存/质量验收。
- **C++评估**：腿力模式默认读取每次评估的当前actor/normalizer，保留原指标与完整闭环，见[接入结果](../native_eval/TRAINING-INTEGRATION-RESULTS.md)。其他未接入模式保留原后端。
- **阶段耗时**：正式训练默认记录准备、首段JIT/训练、后续采样/PPO、评估、快照、IO及保存；CUPTI设备采集仍是独立诊断，未常驻训练。见[计时合同](TRAINING-TIMING.md)。
- **缓存与预览**：沿用生产的持久JAX编译缓存、阶段预检缓存和打开时单次同步的预览机制，没有为占满显存增加预分配，也未修改缓存身份规则。

求解器迭代上限、物理后端切换、奖励/学习率、采样/PPO的C++重写以及高频回调削减尚未作为本轮默认优化应用。

## 真实短训验收

从已验证的1,171,456步模型显式选择`throughput512`，通过原监督器完成唯一120秒短续训，run为`20261115T081557.290279Z_bd32fd40`。实际训练120.1705秒、新增2,801,664步，预算吞吐约23,314步/秒；含准备/保存的计时窗口130.2487秒，约21,510步/秒。准备9.4065秒，收尾0.6566秒。

首段含JIT/计算9.8679秒，后续采样/PPO97.0299秒；三次完整评估合计1.5012秒，其中原生闭环0.6515秒。首次reset缓存/启动状态与历史不同，不能把评估的全部差异归给并行数。正式阶段计时没有额外逐步同步。JSONL重建与sidecar一致、归账残差0，记录开销0.3106秒（0.238%）。更高吞吐使快照/进度等CPU回调占用约7.764秒，IO约2.003秒；后续可单独研究其频率和序列化成本。

相对上次128环境的历史记录，训练预算吞吐约2.4倍；起始checkpoint及缓存状态不同，这只是记录对照，不能当作严格因果A/B或长期保证。统一批量计算对照的3.28倍也不能直接作为完整训练收益。

最终保存模型另用CPU/C++、相同8组缓存真实reset进行600步确定性站立评估，避免用训练中途策略替代最终checkpoint。初始平均回报8578.238，最终10756.361（约+25.39%），8回合均600步；通过事先声明的长度和最多10%回报下降门槛。此为名义站立短验收，没有验证扰动、速度跟踪、长期收敛或不同控制方法。

模型重载误差0，导出最大误差2.384e-7，6组actor叶有更新，固定normalizer漂移0。新checkpoint为`000002801664`，输入旧checkpoint及源指纹保持不变；控制台重启后inactive/can_resume=true，显示512环境，预览关闭。

CPU回归79项全部通过，包含默认选择/旧配置继承、实际kwargs和持久记录一致、损坏配置失败日志、原停止保存/计时及原生评估适配。生产仅定点更新运行模块、包装入口和页面环境数显示；没有同步暂停中的实验开关或并行UI半成品，没有推送。
