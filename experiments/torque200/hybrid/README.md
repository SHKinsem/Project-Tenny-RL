### 模式与频率分开选择

`virtual_leg_force`、`matched_envelope`、`direct_torque` 均可独立选 `control_hz=100` 或 `200`，默认仍 200。启动网页（8800）的这两项任务也有单独的频率下拉框。这里的“支持”表示接通配置与验证入口，不表示两种频率已通过本机动态测试或能够稳定平衡。50/150/400 Hz 等暂时明确拒绝，不静默取整或退回默认。

- 物理与腿力映射固定 400 Hz。100 Hz 每个动作保持 4 个物理子步（10 ms），200 Hz 保持 2 个（5 ms）；每个物理子步重新计算几何，不把映射一起降频。
- episode 保持 6 秒，命令的首次重采样保持 0.2 秒、之后每 3 秒。reset 时仍保留原随机初始命令，不等于最初 0.2 秒强制零命令。新实验修正了旧计数器 `>` 导致的周期多一控制步；旧 torque200 不变。
- 默认动作延迟仍为 0。内部延迟测试固定 10 ms，分别是 1/2 个策略步，不把相同延迟步数误当相同延迟时间。非整策略周期的延迟拒绝，不做近似。`HybridPolicy` 主机适配器仅接受训练入口的零延迟模型，不隐藏增加一层延迟队列。
- 奖励总和仍乘 `ctrl_dt / 10 ms`。实际扭矩能耗和一/二阶变化代价在 400 Hz 子步平均后积分；跟踪/姿态项仍为策略周期末采样，不声称是全子步积分或跨频率完全等价。折扣按 0.5 秒半衰期换算；GAE 的 λ 按 200 Hz 时 0.95 的同一时间衰减换算。
- `steps` 和 `unroll_length` 仍明确表示策略 transition 数，不是秒。同样 16 步在 100/200 Hz 分别为每条序列 0.16/0.08 秒；PPO 总 steps 跨并行环境累计，报告另写累计仿真秒数和单条 rollout 秒数。跨频率对照应匹配实际时间和种子，不是仅用相同步数；优化器更新次数、熵系数及样本相关性仍需实验调参。
- 每次 gate 只验证所选频率的三种模式，报告和训练要求一致。换频率必须重新运行完整 gate，并重新训练，不能加载另一频率或旧版本模型。checkpoint、导出和主机适配器都保存/核对频率、物理步长和子步数；适配器默认读取模型保存的频率，不套用界面默认值。
- 原版预训练 `original` 仍固定100 Hz，原 `torque200` 入口仍为200 Hz。完整控制台已接入新混合模型，后端使用对应的混合环境与模型适配器；三模式和两频率分别保存，不使用旧全扭矩预览器加载新模型。Windows启动器提供本机转发地址，以页面链接为准。

## 控制对象和数学定义

当前模型每侧只有一个主动腿关节（髋）和一个驱动轮；膝由多项式 equality 耦合，不是两个独立可控腿关节。四个动作顺序固定为左腿、右腿、左轮、右轮。

- H 是髋轴中心 `thigh_*_site`，C 是轮轴中心 `wheel_*_site`，`l=|C-H|`。
- `qk = knee_ref + P(qh-hip_ref)`。角度以关节 `ref` 为准，不把 body 的 Euler 初始姿态当作关节角。
- `Jl = ∂l/∂qh + P′(qh-hip_ref) ∂l/∂qk`。当前结构 H 与髋轴重合，固定膝角时腿整体绕髋转动不改变长度，所以第一项为零。
- `Fv > 0` 定义为伸长腿；`tau_hip = Jl * Fv`。当前实验区间两侧 Jl 都为负，正伸展力对应负髋扭矩。这不是符号错误。
- 只做乘法，不除 Jl，不用绝对值掩盖方向，不加 `mg/2` 偏置、PD、LQR 或外部 `xfrc_applied`；轮扭矩独立，轮反作用由仿真动力学自然产生，不另加一次髋补偿。
- 这是轮心轴向**虚拟广义作用**，不是测得或保证实现的轮地接触合力。不需要臆测接触点或地面力方向，也不能把动作当作真实载荷传感器值。

| 新模式 | 髋扭矩 | 轮扭矩 |
|---|---|---|
| `virtual_leg_force` | `Jl(qh,qk_actual) * Fs * a_leg` | `0.0295 * a_wheel` N·m |
| `matched_envelope` | `abs(Jl) * Fs * a_leg` | 同上 |
| `direct_torque` | `1.0 * a_leg` N·m | 同上 |

动作先裁到 [-1,1]，最终扭矩限幅为 [1,1,0.0295,0.0295] N·m。matched-envelope 是幅值包络对照，不是额外控制器。当前 Jl 始终为负，因此把 force 模式前两维动作取反后，matched 模式应逐步得到相同动力学，预检会验证这一点。

## 校准范围、时序与失效处理

新三模式统一采用髋角软件实验区间 [-0.5,0.05] rad，不是已经测量的机械限位。它保留原 `qpos0=0` 重置，末端多留 0.05 rad；不擅自将初姿改到可能使轮穿地的位置。

源码 XML 数学扫描给出两侧约 `Jl ∈ [-0.100444,-0.084491] m/rad`，长度约 33.7–87.1 mm。密集扫描再局部加密，采样最大 |Jl| 上浮 1%，以 `Fs=0.9*1 N·m/Jmax` 得到约 8.8715 N。它是保守数值候选，不是解析认证的全状态界限；模型或源码变化后必须重新验证。

策略按所选频率每 5 或 10 ms 给一次动作，400 Hz 的每个物理子步重新读取实际髋/膝角计算几何，再发送扭矩。保留原策略延迟队列，先延迟动作再在新状态映射。不会每步强制投影膝角来伪造理想约束。

以下任一条件会清零后续子步命令并锁存本步终止，即使下一子步回到区间也不恢复：
- 髋角超实验区间、非有限动作/几何/状态；
- 膝 equality 位置残差超过 0.01 rad；
- equality 速度残差引起的腿长速度误差超过 0.05 m/s；
- `abs(Jl)/Jmax < 0.05` 的退化区。

这些容差是初版数值诊断阈值，不是实物保护设计。默认重置的膝 equality 残差约 0.0004 rad 被明确保留并记录。实际参数、残差峰值、裁剪比例和退化比例写入验证/训练指标；若首次本机预检失败，应排查模型而不是自动放宽阈值。

## 公平对照与旧版本隔离

原 `reference/` 100 Hz 模式、原 `test-torque200` / `train-timed` 入口和默认动作语义保持不变。基础 200 Hz 环境仅抽出等价控制 hook；新行为全部在子类中。

新三模式使用相同 24D actor / 51D critic、时间步、延迟、限幅、软件终止范围、网络、奖励与随机化配置。首阶段关闭额外推力课程，保留既有模型参数随机化。使用相同种子和时间步比较，后续应多种子验证。

新观测末四维是刚结束控制周期全部子步**最终发送扭矩的均值 / 各轴扭矩上限**，不是原始 Fv 动作。能耗项按子步实际 `qfrc_actuator` 归一化平方平均；变化率按实际扭矩的子步一/二阶差分计算后时间平均，参考时间为 10 ms。既不是 `ctrl` 原值，也不是含接触/重力/约束的总广义力。自动重置清空扭矩历史和延迟队列，避免跨 episode 污染。

因此新三模式可互相对照，但与旧 torque200 的奖励绝对值不能直接等同；应另外比较站立时长、跟踪误差、实际扭矩、失效比例。

## 验证和检查点

不装 ML 依赖即可在仓库根目录运行：

```bash
python -m unittest discover -s tests -v
cd experiments/torque200
python -m hybrid.validate --static-only --output results/hybrid-static.json
```

`--static-only` 明确输出 `runtime_validated=false`，不能拿来启动训练。完整验证需去掉该选项，会检查：
1. 编译后关节/执行器次序、gear、静态增益、限幅、约束方向、ref、积分器与模型参数；
2. 轮心位置、解析 Jl 与 MuJoCo site Jacobian、有限差分和 JAX vmap 的一致性；
3. 三模式短 rollout、force/matched 等价、直接扭矩的原物理路径一致性；
4. 实际扭矩/观测/代价、延迟、越界与约束无效清零；
5. JIT reset/step、vmap、State scan、训练用 domain randomization + Brax wrapper + auto-reset 路径；
6. 所选频率的缓存形状、实际仿真时间步，以及命令重采样/计数器周期边界。边界检查注入计数器，不伪称机器人已稳定运行 3 秒。

只有当前源码指纹的完整验证通过，训练入口才放行。训练后还会检查损失、参数有限性、检查点保存/重载、NumPy 导出与 JAX 输出及动作适配器一致性。热启动额外检查策略/价值网络权重确实改变，单独归一化统计变化不算继续学习。这里是权重与归一化恢复，优化器重新初始化，不宣称精确续训。

检查点的模式、控制频率、物理频率、子步数、动作顺序、观测语义、维度、尺度、范围、源码指纹必须一致；检查点文件树和导出文件另用 SHA256 绑定。缺元数据、旧 24D 模型混入、错误模式、内容变化均拒绝。需要改模型或代码时，应显式重新校准/训练，不自动迁移旧权重。

`HybridPolicy` 只是主机验证适配器。调用 `torque` 必须传实际左右髋/膝角和速度，在 400 Hz 更新；它不直接操作硬件。导出的 C 数组不包含机器人控制、安全检查、传感器同步或完整 C 几何实现，**不能直接刷到真机驱动电机**。

### 热启动结构校验修复

Brax PPO 返回的最外层参数是 `(normalizer, policy, value)` 元组，而本项目的 Orbax 元数据加载器构建列表。JAX 将列表和元组视为不同树，因此直接比较两者的 `[1:]` 会误报结构改变。本次仅统一这一层容器；内部 JAX 树、参数键路径、shape、dtype、有限性仍严格检查，归一化变化仍不算网络学到了东西。网络节点限于普通 dict/list/tuple 和实际 NumPy/JAX 浮点数组；未知自定义容器或数组投影对象会拒绝并记录诊断，不能静默漏查其中的参数。失败时不得删除断言或放宽模型维度。

热启动会保存 `restore_network_check.json`，列出实际前后外层类型、内部容器、参数路径和叶子的类型/shape/dtype，不包含权重数值。成功报告另含检查叶子数、改变的网络叶子数和最大变化。该改动修复了确定的源码比较缺陷，但旧日志未打印实际树，不能仅凭旧报错证明不存在其他不匹配。

用户提供的旧版本日志中：本机动态预检成功，首轮 16 步的保存/重载/导出检查成功；热启动又完成 16 步并保存/导出，但最后结构比较失败，因此整套冒烟测试未通过。首轮训练含编译计时约 145 秒，总耗时约 195 秒；热启动的底层训练计时约 63 秒，但没有成功的最终报告。这些不是本修复版本的动态通过证据。更新源码后按现有指纹规则重跑完整 gate，不复用旧验证报告或手工把失败报告改成成功。

依据：[Brax v0.14.2 PPO 源码](https://github.com/google/brax/blob/v0.14.2/brax/training/agents/ppo/train.py)、本仓库 `legwheel/deployment/extract.py` 的元数据加载路径。

### 网页训练与准备时间

网页沿用原训练管理器，运行记录位于 `tenny-torque200/artifacts/console/hybrid_<模式>_<频率>/`；CLI和网页共享 `tenny-hybrid200/readiness-cache/` 准备证据及互斥锁。准备检查耗时单独显示，不消耗混合动作的训练时长；正式训练的初始化、JIT与评估计入训练时长，保存验证另计。没有固定的首次编译耗时承诺。

停止准备会取消当前阶段，保留此前已经通过的阶段凭据；下一次只补未完成或失效阶段。训练中停止则在安全回调边界保留参数并保存验证。关闭浏览器不停止训练。续训恢复网络和归一化参数，优化器重新初始化。画面每次打开时同步一次策略，观看期间固定版本；无兼容模型时明确显示不可预览，不使用其他模式的权重替代。

缓存命中检查不导入JAX、不进行模型编译，但仍读取环境标识与证据。阶段实际依赖的源码、模式频率、依赖/设备/运行设置变化或证据损坏会使相关阶段失效；仅编排或HTML展示变化不必重跑数学验证。新增未知相关模块会保守地使阶段失效。旧报告保持原字节与原指纹；仅有可核验的原源码清单、成功退出日志及相同阶段依赖时，才通过独立引用凭据兼容旧证据，普通模型续训仍执行严格校验。
