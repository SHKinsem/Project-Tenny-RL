# 简洁终端与完整日志

`python tenny.py run test-hybrid` 和 `train-hybrid` 默认使用简洁终端输出。训练算法、校验断言、退出码和 JSON 产物不因降噪而改变。

- 保留当前校验阶段、实际完成数量、训练实际步数、评估回报/总损失，以及最终编译加训练时间、总耗时。
- 可见输出超过 15 秒未更新时显示当前阶段和累计运行时间。该心跳由独立日志进程发出，只表示管道尚未结束，不证明编译或设备有进展；不会编造百分比或剩余时间。
- 仅合并两类精确匹配的已知重复提示：XLA 驱动版本字符串格式提示、PjRt 版本兼容性提示。首次显示说明，每阶段结束给出数量；不是将所有 `ERROR`、`WARNING` 或 stderr 隐藏。
- 大段数值指标 JSON、成功报告 JSON 和已知逐层导出调试打印只从默认终端视图折叠。未知输出、未知警告、非有限指标和 traceback 仍显示。
- 只有生产进程退出 0、日志进程成功且落盘报告表明通过，终端才显示该阶段“通过”。任何失败都会停止后续阶段，显示退出码、完整日志入口和最近日志片段。错误尾部片段有长度限制，完整原文不截断。

## 日志入口

每轮开始会打印完整日志路径。工作目录的 `artifacts/<运行编号>/` 内保留：

- `validation.log`：完整预检 stdout + stderr；`validation.json`：全部检查与每阶段耗时。
- `train.log`、`restart.log`、可选 `requested.log`：对应训练完整 stdout + stderr。
- `first/`、`restart/`、可选 `requested/` 内的 `progress.json`、`status.json`、`report.json`：完整指标、状态和最终报告。

日志按可用字节立即写入文件，不等待换行，然后再增量解码与筛选终端视图。终端断开或展示处理失败时，仍继续接收完整原始日志至当前子进程结束，再以非零退出阻止后续阶段。无效 UTF-8 字节也保留；不会覆盖已有同名日志。源码导出、检查点和旧运行产物不删除。runner 仍会把日志/报告复制至仓库已忽略的 `experiments/torque200/results/hybrid-<运行编号>/`。

如需原始详细终端输出，在 WSL/Linux 中设置 `TENNY_VERBOSE=1` 再运行；或直接打开上述日志。直接运行 `python -m hybrid.validate` / `hybrid.train` 的原始输出保持不变。

Windows 在启动 WSL 之前生成的 localhost 代理提示不属于这些子进程日志，本改动不改 WSL 代理设置、不隐藏该提示，也不修复它的编码。更新只影响之后启动的任务，不会改变已运行进程。请等当前任务结束后再拉取，不并发同步同一个训练工作目录。

## 已验证范围

主机侧回归覆盖 JSON 摘要、精确提示合并、未知错误透传、原始字节完整、日志防覆盖、无换行即时落盘、终端断开后继续落盘、超大指标值、子进程等待心跳、pipefail、生产进程失败与缺失报告的停止行为。另用已提供的成功运行日志做离线重放，确认原始字节完整落盘且输出明显缩短。离线重放和模拟进程测试都不是新版 JAX/MuJoCo/PPO 动态验证；完整本机训练仍需本机实际运行。

日志模块与 runner 属于已有源码指纹覆盖范围。更新后按原有规则重新运行完整 gate，不修改旧检查点的源码指纹来绕过校验。16 步管线成功仍不代表平衡、收敛或实机通过。
