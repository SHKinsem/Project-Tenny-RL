# 原机器人全扭矩 200 Hz 独立实验

这是原参考机器人环境的独立副本，目标是验证全扭矩接口与短训练流水线。
没有迁移 Tenny 机构，没有编译或烧录 ESP32，也没有覆盖原演示策略。

## 启动

在 Project Tenny 根目录的 PowerShell 中运行：

```powershell
pwsh -File .\test-torque200-training.ps1
```

默认执行环境回归测试，然后进行两轮各 16 个累计环境步的 PPO；第二轮加载第一轮参数。
两轮各使用 2 个训练环境、2 个评估环境。此规模只验证流水线，不足以学习平衡。
脚本创建带时间戳的新输出目录，不覆盖以前的结果。

Windows 保存源码，执行时复制到 WSL ext4：

- 实验源码：`~/projects/tenny-torque200/src`
- 结果：`~/projects/tenny-torque200/artifacts/<运行时间>/`
- 复用 GPU Python：`~/projects/tenny-reference/.venv-gpu/bin/python`
- Windows 报告：本目录 `results/<运行时间>/`

Orbax checkpoint 保留在 WSL；报告、日志、CPU 参数快照及导出数组复制回 Windows。
原版仍使用项目根目录的 `start-simulation.ps1` 与 `test-gpu-training.ps1`。
训练启动器不渲染窗口，也不会将短训练权重装入原版演示。

### 看实时效果

在项目根目录执行：

```powershell
pwsh -File .\start-torque200-preview.ps1
```

自动选择最近完成保存/导出验证的 resumed checkpoint，打开独立 MuJoCo 窗口。
首次先编译预热，窗口出现后显示机器人、四路目标扭矩、回合时间和计算速度。
空格暂停/继续，R 重置，滚轮缩放，X 或关闭窗口退出。终止姿态停留0.7秒后自动重置。
只看模型推理，不启动训练；模型在本次窗口运行期间固定，不自动热更新。

使用原实验 MJX step 和200Hz控制时序，CPU推理/物理仿真，OpenGL渲染目标30fps。
为方便观察，评估使用零指令、无观测噪声、无推力、无域随机化；不是训练时的随机评估条件。
CPU后端避免占用CUDA训练计算，但显示仍消耗CPU/图形资源；同时训练的减速尚未测量。
若机器繁忙，显示和仿真可变慢；策略的仿真步长保持5ms。

可用 `-Seconds 8` 自动关闭验收窗口。关闭时将日志、截图、报告复制到
`experiments/torque200/results/preview-<时间>/`。

## 与原版的最小差异

| 项目 | 实验设置 |
|---|---|
| 机器人 | 原质量、惯量、轮径、连杆约束、地面与被动物理参数 |
| 动作 | 左腿、右腿、左轮、右轮，4 路绝对关节输出端扭矩 |
| 归一化动作 | `[-1, 1]`，超范围裁剪，无扭矩累加器 |
| 扭矩尺度 | `[1.0, 1.0, 0.0295, 0.0295]` N·m |
| 时间 | 策略 5 ms，物理步 2.5 ms，每策略步 2 子步 |
| 回合 | 6 秒 / 1200 步；命令周期仍为 3 秒 |
| 网络 | Actor 24→64→64→8；Critic 51→512→512→512→512→1 |
| 观测 | 删除 6 维旧轮速度环状态，增加 4 维上次实际发送的归一化扭矩指令 |
| 大腿速度 | 使用原噪声尺度的真实关节速度，不再替换为纯噪声 |
| 执行器 | 四个 gear=1 torque motor；无位置/速度伺服偏置 |
| 随机化 | 保留原物理扰动；大腿 kp/kv 随机化替换为扭矩增益 0.9–1.1，轮增益仍为 0.8–1.2 |

腿部 1 N·m 是本次流水线实验的初始动作尺度，不是已经优化或验证足以平衡的值。
轮子保留原环境 0.0295 N·m 限制。随机增益之后仍受执行器力矩限幅约束。
`applied_torque` 指发送给执行器的目标扭矩，不是含随机增益后的实测力矩。
当前仿真使用理想力矩执行器，没有显式模拟 10–20 kHz 电流环、电流带宽或新通信延迟。

## 奖励与时间尺度

- 保留速度/转向、位置/朝向保持、实际腿角度高度跟踪、横滚和原有姿态项。
- 删除把腿部控制输出与目标角度比较的 `tracking_height_action`。
- effort 代价为四路 `mean((torque / scale)^2)`，不代表真实电能消耗。
- 保留原动作一阶/二阶绝对差形式，分别乘 `reference_dt/dt` 和其平方。
- 连续总奖励乘 `dt/0.010`，维持原每秒尺度；事件终止惩罚单独处理，默认仍关闭。
- 折扣继续使用 0.5 秒半衰期，200 Hz 时约 0.9930925。
- 正式入口默认 rollout 150 步，对应原先 75 步的 0.75 秒；短训练 harness 仍用 4 步以控制开销。
- 不同时调大俯仰奖励或加入新的课程/控制器，训练效果尚待后续验证。

## 保存与导出验收

复用原 PPO、Orbax 保存/加载、CPU 参数快照和 C 数组导出器。
NumPy 推理核由原部署实现复制，仅适配 24 维输入并解除对旧固件权重的绑定。
每次导出附带 `policy_metadata.json`，记录动作顺序、单位尺度、网络尺寸和控制周期。

验证包含：

- 环境接口、扭矩符号/限幅、零动作无伺服力、延迟、观测及奖励时间缩放。
- GPU 参数树、训练进度、checkpoint 文件实际生成。
- 全部保存前参数与重载参数精确一致、有限值检查（含 Critic 和探索尺度）。
- 8 组观测（包含推进后的动态状态）上训练端/重载/NumPy 导出动作对照。
- 导出数组保留 6 位小数，动作最大绝对误差阈值为 `1e-3`。
- 从新实验 checkpoint 加载参数继续训练，并检查网络参数实际改变。
- 原 Windows/WSL 源文件指纹保持不变。

这里的恢复是加载策略、价值网络及归一化参数继续训练；不宣称恢复完整优化器状态，
也不将两轮各16步的进度当作无缝累计计数。

## 当前边界

原 XML 的腿关节没有显式机械行程限制；之前的 `[-0.5,0]` 是位置目标范围。
全扭矩版本保留原物理模型，该范围现在仅用于指令/奖励，不保证实际腿角度不越界。
长期运动范围、平衡、抗扰、收敛和实机能力均未验收。

支持的入口是独立短训练启动器和上述 preview 启动器。复制保留的旧调参搜索空间与可视化观测标签尚未
全面适配，不应直接沿用旧调参方案；原版演示入口保持原状。

## 网页实时画面

项目根目录执行 `pwsh -File .\start-torque200-web.ps1`。等待 WEB_READY 后，在浏览器打开终端打印的 WSL 地址（端口默认8770）。WSL重启后IP可能变化，以启动器输出为准。

网页提供实时画面、暂停/继续、重置、显示开关、四路目标扭矩及回合时间。渲染为800×500、目标20fps；仿真控制仍为200Hz。无浏览器画面连接或关闭画面计算时，自动停止仿真与渲染。服务关闭用启动终端Ctrl+C。没有改防火墙或建立公网入口。

GPU负责PPO训练；独立网页进程用CPU完成单机器人策略推理和MJX物理仿真，OpenGL绘图仍消耗图形资源。网页展示固定保存模型，不直接显示训练环境；新模型保存验证后重启网页服务加载。

### 稍长训练的性能对照

先打开网页并保持“继续”和画面计算开启，然后执行 `pwsh -File .\test-torque200-performance.ps1`。测试会自动切换关闭/开启/开启/关闭画面四轮，结束恢复原状态。期间不操作网页控制按钮。每轮从相同checkpoint/seed开始，16训练环境、rollout16步、实际32768累计环境步；四轮共131072步，不是同一个模型连续训练131072步。每轮共4个8192步区间，前两个区间不计入稳定吞吐，后两段合计16384步用于比较。最初4608步试跑暴露了延迟预热和计时窗口过短问题，其pilot数据不用于最终干扰百分比。

A条件是浏览器保持打开但仿真/渲染关闭；B条件保持一个实际浏览器实时接收画面。指标不能当作“完全退出浏览器”的比较，也不能外推到大批量训练。每轮都验证保存/加载、有限loss及导出一致性。报告位于 results/performance-<时间>/。

本次实际验收由用户提前结束：正式对照仅完成A1/B1各32768步，B2已停止，A2未运行。约13.1%的吞吐下降是单组初步结果，不是完整ABBA统计；已完成轮次的模型保存与导出验证通过。

## 轻量GPU并行优化结果

入口 `pwsh -File .\test-torque200-throughput.ps1`。测试预算300秒，单档100秒，停止和清理可能额外耗时数秒；超时不扩大测试。使用真实PPO采样和更新，但在独立诊断子进程中跳过效果评估，仍检查保存/恢复与导出。

本次 throughput-20261114-163516 约192秒完成16/64/128环境各32768步。后两段合计16384步测得约1580/3598/9582步每秒；128档相对16档约6.1倍。64档两段波动大，128档有效计时仅1.71秒，均为初步吞吐，不宣称稳定极限。设备总显存采样峰值分别3364/3601/3492MiB，不是训练进程独占显存。

候选参数见 throughput-128-candidate.json，原训练默认值未覆盖。增加环境时SGD批量也增大，单位样本的更新行为变化；吞吐提升不等于收敛速度同比提升。没有替换网页中的已评估B1模型。

## 学习曲线

统一控制台 `/` 同时显示实时机器人、指标卡片和单次训练运行的真实回合秒数、奖励及Value/Policy Loss。顶部“学习曲线”跳到同页 `/#learning`，旧 `/learning-curves` 地址自动跳转，不再单独显示另一套页面。数据来自所选运行progress.json，每10秒重读；网页本身不启动训练，不拼接其他实验。有定时训练时读取本轮实时记录，否则回退到已验证B1。每次2个评估环境，均值有噪声；时长不是成功率，Loss下降不等于平衡能力改善。

只看曲线时可点“关闭画面计算”，无需离开控制台；后端无画面客户端时也不执行展示仿真/渲染。界面使用同一套深色卡片、字体和图表样式。


## 128环境、15分钟定时训练

项目根目录执行 `pwsh -File .\start-torque200-training.ps1`。该入口仅使用原机器人全扭矩200Hz独立副本，128训练环境、2评估环境，batch128、rollout16、每批一次更新。加载已验证B1的策略、价值网络和归一化参数；新运行内保持一次连续PPO调用，不反复重建优化器。

默认预算900秒，包含导入、预热、采样、更新和评估；截止前停止安排新训练工作，在边界退出，随后单独完成保存、重载和导出验证。每约45秒记录一次真实评估并保存中间checkpoint，loss按训练区间更新。网页画面默认关闭，曲线每10秒读取，顶部显示倒计时和保存状态；画面开关只影响展示，不能暂停训练。

新的运行以 `training-<时间>` 保存，实时状态通过training-status.json / training-live.json发布。最终验证通过后才更新training-latest.json。原模型不覆盖。训练中的曲线尚未代表最终验收；缺少评估的loss记录不会伪造奖励或回合时长。网页展示的模型在服务启动时加载，训练结束后重启网页服务即可加载已验证的新模型。


## 原版一键切换

统一网页现在支持原版（腿位置＋轮速度，100Hz，26维观测）和本实验（全扭矩，200Hz，24维观测）两个模式。通用入口是根目录start-robot-web.ps1；网页按钮切换展示和下一次短验证的模式，现有训练不受影响。完整说明见根目录CONTROL-MODES.md。原版展示作者预训练模型，曲线明确标为独立原版短训练记录，不能把两者当作同一训练成果。


## 完整训练控制台

日常训练改为统一网页：定时/不限时、开始新训练、停止并保存、从最近模型继续、载入最新模型。无需运行16步诊断脚本。关闭网页不停止训练，训练与保存期间锁定模式。继续恢复网络和归一化，优化器重建。停止在当前计算段边界完成，首次编译可能延后截止；完整说明见根目录CONTROL-MODES.md。新控制台产物独立位于artifacts/console/<mode>/<run>/，不覆盖旧实验。
